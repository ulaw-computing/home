In the last lesson, you requested a single set of values from an API. Many APIs send back a list of results instead, such as search results, and real data is rarely tidy: some results have missing values, and some searches find nothing at all. In this lesson you will build a book search page using the Open Library API, display its results as cards, handle missing and empty data, and let users sort and filter the results.

The starter code contains the search page and its styles. Complete each Try It section in the editor before moving on.


The Open Library Search API

Open Library is a free online catalogue of books, run by the Internet Archive. Its search endpoint needs no key, uses HTTPS and supports CORS. Its documentation is at openlibrary.org/dev/docs/api/search. A request uses these options:

  • q: the words to search for.
  • fields: a comma-separated list of the information you want about each book. Asking only for what you need keeps the response small and fast.
  • limit: the maximum number of results.
function buildSearchUrl(searchTerm) {
    const params = new URLSearchParams({
        q: searchTerm,
        fields: "key,title,author_name,first_publish_year,cover_i",
        limit: 20
    });
    return `https://openlibrary.org/search.json?${params}`;
}

Exploring the Results

Look carefully at a few of the objects in docs. They do not all have the same properties. Here are two results from a typical search:

{
    "key": "/works/OL1234567W",
    "title": "Learning Web Design",
    "author_name": ["Jennifer Niederst Robbins"],
    "first_publish_year": 2001,
    "cover_i": 1234567
}

{
    "key": "/works/OL7654321W",
    "title": "Web Design Notes"
}

When Open Library has no information for a field, it leaves the property out altogether. Reading a missing property gives undefined, and if your code displays it, users see the word undefined on the page. Worse, if your code calls a method on it, such as book.author_name.join(", "), the code stops with an error, and the rest of the results never appear.

Notice too that author_name is an array, because a book can have several authors, and that the cover is a number rather than an image address.

ℹ️ Info: Never assume that every item from an API has every property. Check the documentation, and look at several results, not just the first one, before you write code that displays them.

Handling Missing Values

JavaScript has two operators that make missing values easy to handle. You met the nullish coalescing operator, ??, in lesson 4: it gives a fallback when a value is null or undefined. The optional chaining operator, ?., is its partner: it reads a property or calls a method only if the value before it exists, and gives undefined instead of stopping with an error if it does not:

// Works whether or not the book has an author_name array
const authors = book.author_name?.join(", ") ?? "Unknown author";

const year = book.first_publish_year ?? "Year unknown";

Read the first line as: if there is an author_name array, join it into a string; if there is not, use Unknown author.


Cover Images

Open Library's documentation explains that the cover_i number is used to build an image address, with a letter for the size: S, M or L:

https://covers.openlibrary.org/b/id/1234567-M.jpg

A book without a cover_i needs something else in its place. The starter CSS has a .no-cover class for a plain placeholder.

When Nothing Is Found

A search that finds nothing is not a failure: the request works, and the API sends back an empty docs array. Without extra code, the page simply shows nothing, and the user cannot tell whether the search finished. Always check for an empty result, and say so:

if (books.length === 0) {
    statusMessage.textContent = `No books were found for "${searchTerm}". Try different words.`;
} else {
    statusMessage.textContent = `${books.length} books found.`;
}

It is also wise to protect your code against data that is not the shape you expect. If data.docs were missing, data.docs.forEach would stop with an error. The ?? operator can provide an empty array instead:

const books = data.docs ?? [];

Finally, do not send a request for an empty search. Check the search term first, and ask the user to type something.

Keeping the Results

To sort or filter the results, your code needs to keep them after they have been displayed, rather than only using them inside searchBooks. Declare a variable at the top level of your code, outside any function, and store the results in it:

let books = [];

async function searchBooks() {
    // ...
    books = data.docs ?? [];
    renderBooks();
}

Then move the code that clears the list and appends the cards into its own function, renderBooks(). Sorting and filtering can then call renderBooks() to redisplay the stored results, without sending a new request. This is faster for the user, and kinder to the API.

Sorting the Results

JavaScript arrays have a sort() method, which takes a compare function. The function is given two items, a and b, and returns a negative number if a should come first, a positive number if b should come first, or zero if their order does not matter.

For numbers, subtracting one from the other gives exactly this:

// Oldest first: smaller years before larger ones
sorted.sort((a, b) => a.first_publish_year - b.first_publish_year);

// Newest first: swap a and b
sorted.sort((a, b) => b.first_publish_year - a.first_publish_year);

For text, use the localeCompare method, which compares strings alphabetically, following the rules of the language, rather than by character codes, which would put every capital letter before every lower-case one:

sorted.sort((a, b) => a.title.localeCompare(b.title));
⚠️ Warning: sort() changes the original array, rather than making a new one. If you sorted books itself, the original order from the API, which is ordered by how well each book matches the search, would be lost. Sort a copy instead, made with the spread syntax: const sorted = [...books];

Books with no year need care. Subtracting undefined gives NaN, which leaves the order unpredictable. A fallback year solves this: using Infinity for oldest first, and -Infinity for newest first, puts books with no year at the end of the list either way:

sorted.sort((a, b) => (a.first_publish_year ?? Infinity) - (b.first_publish_year ?? Infinity));

Filtering the Results

The filter() method, which you met in JavaScript lesson 7, creates a new array containing only the items for which a function returns true. The starter page has a filter box, to show only results whose title or author contains some text. As with the search itself, the comparison is easier if both sides are in lower case:

const filterText = filterInput.value.trim().toLowerCase();

const shown = sorted.filter((book) => {
    const title = book.title.toLowerCase();
    const authors = (book.author_name?.join(", ") ?? "").toLowerCase();
    return title.includes(filterText) || authors.includes(filterText);
});

An empty filter matches every book, because every string includes the empty string.

The filter is different from the search: the search asks the API for new results, while the filter narrows down the results the page already has, instantly and without a request. This is why the filter can update on every key press, using the input event, when the search cannot.

Check Your Page

Your renderBooks function should be similar to this:

function renderBooks() {
    const sorted = [...books];

    if (sortSelect.value === "title") {
        sorted.sort((a, b) => a.title.localeCompare(b.title));
    } else if (sortSelect.value === "newest") {
        sorted.sort((a, b) => (b.first_publish_year ?? -Infinity) - (a.first_publish_year ?? -Infinity));
    } else if (sortSelect.value === "oldest") {
        sorted.sort((a, b) => (a.first_publish_year ?? Infinity) - (b.first_publish_year ?? Infinity));
    }

    const filterText = filterInput.value.trim().toLowerCase();
    const shown = sorted.filter((book) => {
        const title = book.title.toLowerCase();
        const authors = (book.author_name?.join(", ") ?? "").toLowerCase();
        return title.includes(filterText) || authors.includes(filterText);
    });

    bookList.replaceChildren();
    shown.forEach((book) => {
        bookList.append(createBookCard(book));
    });

    if (books.length === 0) {
        resultCount.textContent = "";
    } else if (shown.length === 0) {
        resultCount.textContent = "No books match your filter.";
    } else {
        resultCount.textContent = `Showing ${shown.length} of ${books.length} books.`;
    }
}
