This first lesson covers custom properties, often called CSS variables. They let you store a value, such as a colour, once, and reuse it throughout your stylesheet. The starter code contains a page for a coding club, whose CSS repeats the same values many times. You will tidy it up with custom properties, then use them to add a dark theme and a colour picker. The Problem: Repeated Values

Look at the starter CSS. The club's main colour, #00695c, appears again and again: on the header, the buttons, the links, the card borders and the footer. The same spacing value, 16px, appears in many rules too.

This causes two problems:

  • Changes are slow and risky. If the club changes its colour, every copy of the value has to be found and changed. Miss one, and the page is inconsistent.
  • The meaning is hidden. #00695c does not tell another developer that it is the club's main brand colour. It is just a number.

Custom properties solve both problems.


Declaring and Using Custom Properties

A custom property is a property whose name you choose, starting with two hyphens. It is declared like any other property, inside a rule:

:root {
    --colour-primary: #00695c;
    --space: 16px;
}

The :root selector selects the root element of the page, <html>. Custom properties are inherited, like color and font-family, so a custom property declared on the root element is available to every element on the page. This makes :root the usual place to declare the values used throughout a site.

To use a custom property, put its name inside the var() function, anywhere you would normally write a value:

.site-header {
    background-color: var(--colour-primary);
    padding: var(--space);
}

When the browser sees var(--colour-primary), it replaces it with the value stored in --colour-primary. Change the value in one place, and every rule that uses it changes too.

ℹ️ Info: Because you choose the names of custom properties yourself, you can use British spelling, such as --colour-primary. The names of CSS's own properties, such as color, must still use American spelling. Custom property names are also case-sensitive: --Colour-Primary and --colour-primary are two different properties.
💡 Tip: Name custom properties after their purpose, not their value. --colour-primary still makes sense if the brand colour changes from green to purple, but --green would then be wrong everywhere it is used. This is the same principle as naming classes after what content is, not how it looks.

    • --colour-primary-dark: #004d40;
    • --colour-background: #f5f5f5;

  5. Check the preview: nothing should have changed yet.

What Custom Properties Can Store

A custom property can store any CSS value, not only colours:

:root {
    --font-body: "Open Sans", Arial, sans-serif;
    --space: 16px;
    --radius: 8px;
    --shadow: 0 2px 6px rgba(0, 0, 0, 0.15);
    --speed: 0.2s;
}

Storing sizes, spacing, rounded corners and shadows this way keeps a design consistent: every card uses the same radius, and every section the same spacing. In the next two lessons, you will also store animation timings, such as --speed.

Calculating With Custom Properties

The calc() function performs calculations with CSS values, and works with custom properties too. This lets you build a set of related sizes from one value:

section {
    padding: calc(var(--space) * 2);     /* 32px */
    margin-bottom: var(--space);          /* 16px */
}

.button {
    padding: calc(var(--space) / 2) var(--space);   /* 8px 16px */
}

If --space later changes to 20px, every size based on it changes in proportion. Spaces are needed around * and / in calc() for readability, and are required around + and -.

Try It

  1. Add --space: 16px; and --radius: 8px; to your :root rule.
  2. Replace every 16px in the stylesheet with var(--space), every 32px with calc(var(--space) * 2), and every 8px used for border-radius with var(--radius).
  3. Change --space to 24px, and notice that the whole page becomes more spacious, in proportion. Change it back afterwards.

Fallback Values

var() can take a second value, called a fallback, which is used if the custom property has not been set:

.badge {
    background-color: var(--colour-accent, #4527a0);
}

If --colour-accent exists, its value is used. If it does not, the badge uses #4527a0, a deep purple.

⚠️ Warning: If a custom property's name is misspelt in var(), and there is no fallback, the browser does not warn you. Instead, the property behaves as if it had never been set: an inherited property such as color takes its parent's value, and a property such as background-color goes back to its default, which is transparent. If a style quietly disappears, check the spelling of your custom property names.

Try It

  1. The .badge rule in the starter CSS uses var(--colour-accent, #4527a0). There is no --colour-accent yet, so the badge uses the fallback colour.
  2. Add --colour-accent: #bf360c; to :root. The badge changes to the new colour.

Scope: Changing a Value for One Part of the Page

A custom property does not have to be declared on :root. Because custom properties are inherited, declaring one on any element changes its value for that element and everything inside it, while the rest of the page keeps the original value. This is called the property's scope.

.card.featured {
    --colour-primary: #8a6100;
    --colour-on-primary: #ffffff;
}

Inside the featured card, every rule that uses var(--colour-primary), such as the card's border and its button, now uses the gold colour, with white text on it. Outside it, nothing changes. You do not need to write new rules for the border and the button: the existing rules simply pick up the new value.

💡 Tip: This is one of the most useful features of custom properties. Instead of writing a separate rule for every part of a component that needs a different colour, you change one custom property, and the component's existing rules do the rest.

Try It

  1. One of the event cards has the classes card featured. Add the rule from the example above, and check that only that card's border and button turn gold.

Themes

Custom properties make themes, such as a dark mode, far simpler than in the JavaScript unit. Instead of writing a new rule for every element that changes colour, you redefine the colour custom properties for the dark theme, and every rule that uses them updates automatically:

body.dark {
    --colour-background: #121212;
    --colour-surface: #1e1e1e;
    --colour-text: #eeeeee;
    --colour-primary: #4db6ac;
    --colour-primary-dark: #80cbc4;
    --colour-on-primary: #121212;
}

A rule for body.dark is more specific than :root, and is closer to the elements that use the values, so its values win whenever the body has the dark class. The toggle button from JavaScript lesson 11 then only needs to add or remove the class.

This is also why --colour-on-primary exists. In the light theme, white text sits on the dark teal. In the dark theme, the teal becomes much lighter, so the text on it becomes dark. Because every rule uses var(--colour-on-primary) instead of white, the theme only has to change one value.

⚠️ Warning: A dark theme needs its own colours, not just the light ones swapped. In this example, --colour-primary and --colour-primary-dark become lighter, because the original dark teals would not have enough contrast against the dark background, as links and headings. Check every text and background pair in both themes. Every pair in this lesson has been checked against the 4.5:1 contrast ratio from the CSS unit.
ℹ️ Info: A theme can also follow the user's device setting with no JavaScript at all, by redefining the custom properties inside @media (prefers-color-scheme: dark) { :root { ... } }. Many sites combine both: the media query provides the default, and a button lets the user change it.

Try It

  1. Add the body.dark rule from the example above.
  2. In the JS tab, add a click listener to the #theme-button that toggles the dark class on document.body, and updates the button's aria-pressed attribute, as you did in JavaScript lesson 11.
  3. Click the button. The whole page switches theme, using only the six values in the body.dark rule.

Custom Properties and JavaScript

Because custom properties are real CSS properties, JavaScript can read and change them while the page is running. Changing one custom property updates every rule that uses it, so a single line of JavaScript can restyle a whole page.

  • To change a custom property, use style.setProperty() on the element where it is declared. For a property on :root, that element is document.documentElement, the <html> element.
  • To read a custom property's current value, use getComputedStyle(), which returns every style that applies to an element, and then getPropertyValue().
const root = document.documentElement;

// Change a custom property
root.style.setProperty("--colour-primary", "#283593");

// Read a custom property
const primary = getComputedStyle(root).getPropertyValue("--colour-primary");
console.log(primary);   // "#283593"

Try It

  1. The starter HTML has a colour picker, an <input type="color"> with the ID accent-picker. Add an input listener to it that sets --colour-primary on document.documentElement to the picker's value.
  2. Open the colour picker in the preview and choose different colours. The header, buttons, links and borders all update as you move through the colours.
  3. Choose a very light colour, such as pale yellow, and notice that the white header text becomes unreadable.
  4. Switch to dark mode and try the picker again. Nothing changes. The picker sets --colour-primary on the <html> element, but body.dark redefines it on the <body>, which is closer to the elements that use it. This is scope at work: the value declared nearest to an element wins.
⚠️ Warning: Letting users choose colours is fun, but it can easily break contrast, as you have just seen. On a real site, either offer a set of tested colours to choose from, or check the contrast of the chosen colour with JavaScript and adjust the text colour to match.

When to Use Custom Properties

Custom properties are a tool for keeping a design consistent and easy to change, so use them where they make a real difference:

  • Values that are repeated, such as brand colours, spacing, fonts and rounded corners.
  • Values that change together, such as the colours of a theme.
  • Values that JavaScript needs to change, such as a colour the user chooses.
  • Values that vary between versions of a component, such as a featured card.

A value used only once, such as the width of one particular image, gains nothing from being a custom property, and only adds an extra step for anyone reading the code.

💡 Tip: When you use custom properties in your own projects, write a comment explaining your reasoning, such as /* Theme colours: redefined in body.dark for the dark theme */. A comment that explains why a value is a custom property is far more useful to another developer than one that only says what it is.
