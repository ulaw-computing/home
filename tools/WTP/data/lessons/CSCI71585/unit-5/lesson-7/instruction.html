What Is an API?

An API (Application Programming Interface) is a way for one program to ask another for data or to do something. A web API does this over HTTP: your page sends a request to an address, and the server sends back data, usually as JSON, rather than a web page.

Each address that an API offers is called an endpoint. For example, Open-Meteo has one endpoint for weather forecasts and another for searching place names:

https://api.open-meteo.com/v1/forecast
https://geocoding-api.open-meteo.com/v1/search

The v1 in each address is a version number. If the API's creators change how it works in the future, they can release a v2, and pages that use v1 carry on working.


HTTP Methods

Every request has a method, which says what the request wants to do. Most web APIs follow a style called REST, where the methods have these meanings:

  • GET: read some data. This is what fetch sends unless you say otherwise.
  • POST: create something new, such as a new comment.
  • PUT or PATCH: update something that already exists.
  • DELETE: remove something.

Public APIs that need no account usually only allow GET requests, because anyone could use them. In this unit, you will only send GET requests.


More Status Codes

In the last lesson, you met the status codes 200, 404 and 500. APIs use some others, which are worth recognising:

  • 400 Bad Request: the request itself was wrong, such as a missing or misspelt option.
  • 401 Unauthorized or 403 Forbidden: the request needs a key or permission that it did not have.
  • 429 Too Many Requests: the page has sent too many requests in a short time, and must wait before sending more.

Reading the Documentation

Every API has documentation: a guide, written by its creators, explaining its endpoints, the options each one accepts, and the shape of the data it sends back. You should always read the documentation before using an API, rather than guessing. Open-Meteo's documentation is at open-meteo.com/en/docs, and lets you build an address by choosing options and see the data it returns.

From the documentation, a forecast request needs at least these options, which are added to the address as a query string after a ?, separated by &:

  • latitude and longitude: the location, in decimal degrees.
  • current: a comma-separated list of the current conditions you want, such as temperature_2m (the temperature two metres above the ground).
https://api.open-meteo.com/v1/forecast?latitude=53.80&longitude=-1.55&current=temperature_2m

Try It

  1. Open the address above in a new browser tab. The browser shows the JSON that the API sends back for Leeds.
  2. Find the current temperature in the data. Notice that it sits inside a current object, and that a separate current_units object says which unit it is measured in.
  3. Change temperature_2m in the address to temperature_2m,wind_speed_10m, and reload the tab. The wind speed is now included too.
💡 Tip: Opening an API's address in a browser tab is a quick way to see its data before writing any code. Many browsers display JSON with collapsible sections, and some have a Pretty-print option.

Building the Address

You could build the address with a template literal, but it quickly becomes long and hard to read. JavaScript's URLSearchParams object builds a query string for you from an object, and safely encodes any characters that are not allowed in addresses, such as spaces:

const params = new URLSearchParams({
    latitude: 53.80,
    longitude: -1.55,
    current: "temperature_2m,wind_speed_10m,weather_code",
    timezone: "Europe/London"
});

const url = `https://api.open-meteo.com/v1/forecast?${params}`;

The timezone option asks for times in UK time rather than the default, which is Greenwich Mean Time all year round.

Requesting the Weather

Requesting data from an API uses exactly the same code as in the last lesson. Only the address is different:

async function showWeather() {
    const city = citySelect.value;
    statusMessage.textContent = `Loading the weather for ${city}…`;

    try {
        const response = await fetch(buildWeatherUrl(city));

        if (!response.ok) {
            throw new Error(`The request failed with status ${response.status}.`);
        }

        const data = await response.json();
        console.log(data);
        statusMessage.textContent = "";
    } catch (problem) {
        statusMessage.textContent = "Sorry, the weather could not be loaded. Please try again later.";
        console.log(problem.message);
    }
}

Try It

  1. Add the showWeather function above, and make the #weather-form call it when it is submitted. Remember to call preventDefault() on the submit event first.
  2. Choose a city and click Show weather. Explore the logged data in the console.
  3. Display the city's name in #weather-city, and the temperature in #weather-temperature, followed by the unit from current_units, such as 11.4°C.
  4. Display the wind speed in #weather-wind in the same way.
ℹ️ Info: The request is sent when the form is submitted, rather than whenever the menu changes. Each request uses a little of the API's free service, and sending one only when the user asks for it keeps the number of requests low.

Turning Codes Into Words

APIs often send codes rather than descriptions, because codes are shorter and do not depend on language. Open-Meteo's weather_code is a number from an international standard, which the documentation lists in full. To show it to users, you can look it up in an object:

const weatherDescriptions = {
    0: "Clear sky",
    1: "Mainly clear",
    2: "Partly cloudy",
    3: "Overcast",
    45: "Fog",
    61: "Light rain"
};

const description = weatherDescriptions[data.current.weather_code] ?? "Unknown conditions";

The ?? operator, from lesson 4, provides a fallback if the code is not in the object, so the page never shows undefined.

Try It

  1. The starter JavaScript includes a weatherDescriptions object with all of the codes from the documentation. Use it to display a description of the weather in #weather-summary, with a fallback.

When the API Reports a Problem

When a request is wrong, many APIs send a JSON response that explains why, alongside the error status. Open-Meteo sends a status of 400, and an object with a reason property, similar to this:

{
    "error": true,
    "reason": "Cannot initialize WeatherVariable from invalid String value temprature_2m"
}

This reason is meant for developers, not users. You can read it before throwing your error, so that it appears in the console where you can see it:

if (!response.ok) {
    const problem = await response.json();
    throw new Error(`Status ${response.status}: ${problem.reason}`);
}

Try It

  1. Update your response.ok check to read and include the reason, as in the example above.
  2. Test it: in buildWeatherUrl, misspell temperature_2m as temprature_2m, and submit the form. The user sees your friendly message, and the console shows the API's reason.
  3. Correct the spelling, and check the weather loads again.

Choosing an API

There are thousands of free public APIs, covering everything from books and films to space and sport, and you will choose one for your own projects. Not every API is suitable for a front-end page. Before choosing one, check that it:

  • Needs no key or account. Many APIs need an API key: a secret code that identifies who is making the request. Anything in front-end code can be read by anyone who visits the page, so a key in your JavaScript is not secret, and could be copied and misused. Keys belong on a server, which is beyond this unit. For a front-end page, choose an API that needs no key.
  • Uses HTTPS. Pages served over HTTPS, as GitHub Pages is, cannot request data over plain HTTP.
  • Supports CORS. By default, browsers only let a page read responses from its own website. CORS (Cross-Origin Resource Sharing) is how a server gives other websites permission to read its responses. An API without CORS support works when you open its address in a tab, but not from fetch on another website. The documentation, or a quick test, will tell you.
  • Has clear documentation, so you know what it returns and what its limits are.
  • Has fair limits for your use. Most free APIs have a rate limit: a maximum number of requests in a minute, hour or day. Going over it results in a 429 status.
  • Has terms you can follow. Many free APIs ask you to credit them on your page. Open-Meteo's terms ask for a credit with a link to its website, which is why the starter page already has one in its footer.

Lists such as the public-apis collection on GitHub show whether each API needs a key, uses HTTPS and supports CORS. Look for No under Auth, and Yes under HTTPS and CORS.

⚠️ Warning: Never put an API key, password or any other secret in front-end code or in a public repository on GitHub. Anyone can read it, and automated programs search GitHub for keys to misuse.

Check Your Page

Your JavaScript should now include functions similar to these:

function buildWeatherUrl(city) {
    const location = cities[city];
    const params = new URLSearchParams({
        latitude: location.latitude,
        longitude: location.longitude,
        current: "temperature_2m,wind_speed_10m,weather_code",
        timezone: "Europe/London"
    });
    return `https://api.open-meteo.com/v1/forecast?${params}`;
}

async function showWeather() {
    const city = citySelect.value;
    statusMessage.textContent = `Loading the weather for ${city}…`;

    try {
        const response = await fetch(buildWeatherUrl(city));

        if (!response.ok) {
            const problem = await response.json();
            throw new Error(`Status ${response.status}: ${problem.reason}`);
        }

        const data = await response.json();
        const units = data.current_units;

        document.querySelector("#weather-city").textContent = city;
        document.querySelector("#weather-temperature").textContent =
            `${data.current.temperature_2m}${units.temperature_2m}`;
        document.querySelector("#weather-wind").textContent =
            `${data.current.wind_speed_10m} ${units.wind_speed_10m}`;
        document.querySelector("#weather-summary").textContent =
            weatherDescriptions[data.current.weather_code] ?? "Unknown conditions";

        statusMessage.textContent = "";
    } catch (problem) {
        statusMessage.textContent = "Sorry, the weather could not be loaded. Please try again later.";
        console.log(problem.message);
    }
}

weatherForm.addEventListener("submit", (event) => {
    event.preventDefault();
    showWeather();
});
