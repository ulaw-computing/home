What Is JSON?

JSON (JavaScript Object Notation) is a way of writing data as text. You met it briefly in JavaScript lesson 8: it looks almost exactly like JavaScript arrays and objects.

{
    "name": "Amira",
    "course": "MSc Computing",
    "year": 1,
    "modules": ["Web Technologies", "Programming"],
    "graduated": false
}

Data inside a running program, such as a JavaScript object, only exists in that program's memory. It cannot be saved to a file or sent across the internet as it is. Text can. JSON is the standard way to turn data into text and back, so that it can be:

  • Saved, in a file or in the browser's storage.
  • Sent between a browser and a server, which is how almost every API works.
  • Shared between programs written in different languages: Python, Java and C# can all read and write JSON too.

JSON Rules

JSON is stricter than JavaScript. A JSON value can be a string, a number, a boolean, null, an array or an object, and:

  • Property names must be in double quotes: "name", not name.
  • Strings must use double quotes: "Amira", not 'Amira'.
  • There can be no comma after the last item in an array or object.
  • There are no comments, no functions and no undefined.
⚠️ Warning: A single mistake, such as a single quote or a stray comma, makes the whole piece of JSON invalid, and it cannot be read at all. Because of this, you should never write JSON by building strings yourself. Let JavaScript create it for you, as you will see next.

Converting To and From JSON

JavaScript has a built-in JSON object with two methods:

  • JSON.stringify(value) turns a JavaScript value into a JSON string.
  • JSON.parse(text) turns a JSON string back into a JavaScript value.
const student = { name: "Amira", year: 1 };

const text = JSON.stringify(student);
console.log(text);           // {"name":"Amira","year":1}
console.log(typeof text);    // string

const copy = JSON.parse(text);
console.log(copy.name);      // Amira
console.log(typeof copy);    // object

JSON.stringify can also take two more arguments to make the result easier to read. JSON.stringify(student, null, 2) adds line breaks and indents each level by two spaces, which is useful when displaying JSON or logging it.

When JSON Is Invalid

If JSON.parse is given text that is not valid JSON, it cannot create a value, and it stops the script. You cannot always control the text you are given, so code that parses JSON from somewhere else should be ready for this. JavaScript's try...catch statement lets you do so:

try {
    const data = JSON.parse(text);
    output.textContent = `Valid JSON with ${Object.keys(data).length} properties.`;
} catch {
    output.textContent = "That is not valid JSON. Check the quotes and commas.";
}

JavaScript runs the code in the try block. If anything in it fails, it immediately stops that block and runs the catch block instead, rather than stopping the whole script. The page keeps working, and the user gets a helpful message. You will use try...catch a great deal in the next three lessons.

Object.keys(data) returns an array of an object's property names, so its length is the number of properties.

Web Storage

Browsers give every website a small amount of storage space, called web storage, which JavaScript can read and write. There are two kinds:

  • localStorage keeps data permanently, until it is deleted by your code or by the user clearing their browser data. It is still there after the browser is closed and the computer restarted.
  • sessionStorage keeps data only until the browser tab is closed.

Both work in the same way, as a list of keys (names) and values:

  • localStorage.setItem(key, value) saves a value under a key, replacing any value already saved under it.
  • localStorage.getItem(key) returns the saved value, or null if nothing has been saved under that key.
  • localStorage.removeItem(key) deletes one key and its value.
  • localStorage.clear() deletes everything your site has saved.
localStorage.setItem("username", "Amira");
console.log(localStorage.getItem("username"));   // Amira
console.log(localStorage.getItem("colour"));     // null: nothing saved yet

Each website's storage is separate: a site can only read the data it saved itself, not data saved by any other site. Browsers usually allow around 5MB per site, which is plenty for preferences and small lists, but not for large amounts of data.

ℹ️ Info: In this platform, each lesson has its own separate storage. Anything you save in this lesson cannot be seen by other lessons, and cannot affect the platform itself, even if you call clear(). Resetting your code does not delete what you have saved, so to start again, use removeItem() or clear().

  3. Delete the getItem line too.

Storage Only Holds Strings

Web storage can only hold strings. Anything else you save is converted to a string first, which causes problems:

localStorage.setItem("score", 10);
console.log(localStorage.getItem("score") + 5);   // "105", not 15

localStorage.setItem("topics", ["Revise CSS", "Read chapter 3"]);
console.log(localStorage.getItem("topics"));      // "Revise CSS,Read chapter 3": no longer an array

localStorage.setItem("profile", { name: "Amira" });
console.log(localStorage.getItem("profile"));     // "[object Object]": the data is lost

JSON is the solution. Convert arrays and objects to JSON before saving them, and parse them when reading them back:

const topics = ["Revise CSS", "Read chapter 3"];

// Save
localStorage.setItem("topics", JSON.stringify(topics));

// Load
const savedTopics = JSON.parse(localStorage.getItem("topics"));
console.log(savedTopics.length);   // 2: a real array again

Providing a Default

The first time a user visits, nothing has been saved, so getItem returns null, and JSON.parse(null) also gives null. The ?? operator (the nullish coalescing operator) provides a default value whenever the value on its left is null or undefined:

let notes = JSON.parse(localStorage.getItem("notes")) ?? [];

This means: load the saved notes, or, if there are none, start with an empty array.


Saving a List

Saving fits naturally into the state pattern from the JavaScript unit. The data lives in a variable, the page is built from it by a render function, and now, every time the data changes, it is also saved:

function saveNotes() {
    localStorage.setItem("notes", JSON.stringify(notes));
}

function addNote(text) {
    notes.push(text);
    saveNotes();
    renderNotes();
}

When the page loads, it reads the saved data into the variable, then renders it, so the user sees exactly what they had before.

Remembering a Preference

Storage is ideal for remembering a user's preferences, such as the dark mode toggle from the last few lessons. Without it, the page returns to the light theme on every visit, and the user has to switch it again every time.

function setDarkMode(isDark) {
    document.body.classList.toggle("dark", isDark);
    themeButton.setAttribute("aria-pressed", String(isDark));
    localStorage.setItem("theme", isDark ? "dark" : "light");
}

// When the page loads: use the saved theme if there is one
setDarkMode(localStorage.getItem("theme") === "dark");

A preference like this is a single word, so it does not need JSON.

Try It

  1. Add the setDarkMode function from the example above, and a click listener on #theme-button that calls it with the opposite of the current state.
  2. Switch to dark mode, then make any small change to run the page again. The page stays dark.
💡 Tip: In JavaScript lesson 11, the theme started from the user's device setting. You can combine both: use the saved choice if there is one, and the device setting if not: const saved = localStorage.getItem("theme"); then setDarkMode(saved ? saved === "dark" : prefersDark);.

What Not to Store

Web storage is convenient, but it is not secure:

  • Any JavaScript running on the page can read it, including scripts from other companies, such as analytics or adverts. If an attacker manages to run their own JavaScript on your page, which you will learn about in Lesson 11, they can read everything in it.
  • It is stored unencrypted on the user's device, where anyone with access to the device can read it.
  • The user can change it, so your code should never trust it for anything that matters, such as whether a user has paid.
⚠️ Warning: Never store passwords, payment details, personal information or login tokens in web storage. Use it for things that would not matter if they were seen or changed, such as preferences, drafts and saved lists.
ℹ️ Info: Storage is shared by every page on the same origin: the same protocol, domain and port. On GitHub Pages, every project site you publish lives on the same domain, such as yourname.github.io, so they all share one storage area. If two of your sites both save a key called "theme", they will overwrite each other's values. Give your keys a prefix, such as "cv-theme", to keep them apart.

Check Your Page

Your notes code should be similar to this:

// Saved notes, or an empty list on the first visit
let notes = JSON.parse(localStorage.getItem("notes")) ?? [];

function saveNotes() {
    localStorage.setItem("notes", JSON.stringify(notes));
}

function renderNotes() {
    notesList.replaceChildren();

    notes.forEach((note) => {
        const item = document.createElement("li");
        item.textContent = note;
        notesList.append(item);
    });

    document.querySelector("#notes-count").textContent = `${notes.length} notes`;
}

function addNote(text) {
    notes.push(text);
    saveNotes();
    renderNotes();
}

Also check that the notes and the theme are both remembered when the page runs again, the clear button empties the list, and the JSON checker reports invalid JSON without breaking the page.
