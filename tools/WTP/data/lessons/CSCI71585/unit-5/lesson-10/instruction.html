Dialogs

A dialog is a box that appears on top of the page, to show some information or ask the user for something. A modal dialog blocks the rest of the page until it is closed: the user cannot click or tab to anything behind it. Modal dialogs are useful for short, focused tasks, such as confirming an action or filling in a small form, without leaving the page.

Building an accessible modal dialog from <div> elements takes a lot of code. HTML's <dialog> element does most of the work for you:

<dialog id="details-dialog" aria-labelledby="details-title">
    <h2 id="details-title">Session title</h2>
    <p>Some information about the session.</p>
    <button type="button" id="details-close">Close</button>
</dialog>

A dialog is hidden until JavaScript opens it. aria-labelledby gives the dialog an accessible name from its heading, so a screen reader announces "Session title, dialog" when it opens. Two methods open and close it:

detailsDialog.showModal();   // opens the dialog as a modal
detailsDialog.close();       // closes it

When a dialog is opened with showModal(), the browser automatically:

  • Shows it on top of everything else on the page, in the centre, with a backdrop behind it.
  • Moves focus to the first focusable element inside it.
  • Makes the rest of the page inert: it cannot be clicked, focused or read by a screen reader until the dialog closes.
  • Closes it when the user presses Escape.
  • Returns focus, when it closes, to the element that was focused before it opened, which is usually the button that opened it.

All of these are things that you had to write yourself for the menu in JavaScript lesson 11.

ℹ️ Info: A dialog can also be opened with show(), which shows it without a backdrop and leaves the rest of the page usable. This is a non-modal dialog. Use showModal() whenever the user must deal with the dialog before carrying on.

Which Button Was Clicked?

The session cards are created by JavaScript, and are created again whenever a session changes, so it is easiest to use one listener on #session-list, with event delegation from JavaScript lesson 9. Each card's buttons have a data-action attribute saying what they do, and a data-id attribute with the session's id:

sessionList.addEventListener("click", (event) => {
    const button = event.target.closest("button");
    if (!button) {
        return;
    }

    const session = sessions.find((item) => item.id === Number(button.dataset.id));

    if (button.dataset.action === "details") {
        openDetails(session);
    }
});

Attribute values are always strings, so Number() converts the id before comparing it with the numbers in sessions.

Try It

  1. Add the listener above, and click a session's Details button. The dialog opens with that session's details.
  2. Test it with the keyboard only: tab to a Details button and press Enter. Focus moves into the dialog. Press Tab several times: focus moves between the dialog's controls, and never reaches the cards behind it.
  3. Press Escape. The dialog closes, and focus returns to the Details button you used.

Styling Dialogs

The starter CSS already styles the dialogs. The backdrop behind a modal dialog has its own pseudo-element, ::backdrop, which you can style like any other element:

.dialog::backdrop {
    background-color: rgba(0, 0, 0, 0.6);
}

A dialog that appears instantly can feel abrupt. A short animation, using @keyframes from lesson 3, eases it in. A dialog has the open attribute while it is open, so the animation runs every time it opens:

@keyframes dialog-in {
    from {
        opacity: 0;
        transform: translateY(20px);
    }
    to {
        opacity: 1;
        transform: translateY(0);
    }
}

.dialog[open] {
    animation: dialog-in 0.2s ease-out;
}

@media (prefers-reduced-motion: reduce) {
    .dialog[open] {
        animation: none;
    }
}

Try It

  1. Add the ::backdrop rule and the animation above to the CSS tab, and open a dialog to see them.

Closing by Clicking the Backdrop

Many users expect a dialog to close when they click the darkened area outside it. A click on the backdrop counts as a click on the dialog element itself, so you can check whether event.target is the dialog:

detailsDialog.addEventListener("click", (event) => {
    if (event.target === detailsDialog) {
        detailsDialog.close();
    }
});

This is why the starter CSS gives each dialog no padding, and puts its content in an inner <div> with the padding instead. A click anywhere inside the visible box lands on the inner <div> or its contents, so only a click on the backdrop has the dialog itself as its target.

⚠️ Warning: Only close a dialog on a backdrop click if nothing is lost by doing so. Closing a half-completed form because the user clicked slightly outside it would lose their work. The booking dialog below does not close on a backdrop click.

A Booking Dialog

The booking dialog in the starter HTML contains a short form. Opening it needs a little more work than the details dialog: the code must remember which session is being booked, and clear anything left over from the last time the form was used:

let currentSession = null;

function openBooking(session) {
    currentSession = session;
    bookingSession.textContent = `${session.time} ${session.title}`;
    bookingForm.reset();
    clearError(bookingName);
    clearError(bookingEmail);
    bookingError.textContent = "";
    bookingDialog.showModal();
}

Feedback While Sending

When a form is sent to a server, there is a delay before the reply. During that time, the user needs to know that something is happening, and must not be able to send the same form twice by clicking again. Disabling the submit button, and changing its text, does both:

bookingSubmit.disabled = true;
bookingSubmit.textContent = "Booking…";

Then, as in lesson 5, use try...catch...finally: show success in try, a helpful message in catch, and put the button back to normal in finally, so it is re-enabled whatever happens:

bookingForm.addEventListener("submit", async (event) => {
    event.preventDefault();
    if (!validateBooking()) {
        return;
    }

    bookingError.textContent = "";
    bookingSubmit.disabled = true;
    bookingSubmit.textContent = "Booking…";

    try {
        const result = await fakeSendBooking({
            sessionId: currentSession.id,
            name: bookingName.value.trim(),
            email: bookingEmail.value.trim()
        });

        currentSession.booked = true;
        currentSession.spacesLeft -= 1;
        bookingDialog.close();
        renderSessions();
        pageStatus.textContent = `You are booked on "${currentSession.title}". Your reference is ${result.reference}.`;
    } catch (problem) {
        bookingError.textContent = problem.message;
    } finally {
        bookingSubmit.disabled = false;
        bookingSubmit.textContent = "Confirm booking";
    }
});

On success, the dialog closes and the page updates. The confirmation appears in #page-status, which has role="status", so screen reader users hear it. On failure, the dialog stays open so that the user does not lose what they typed, and the message appears in #booking-error, which has role="alert". An alert is announced straight away, interrupting anything else, which suits a problem that the user must deal with.

The function passed to addEventListener can be async, like any other function, so it can use await directly.

ℹ️ Info: The last step shows why a server must always make the final decision. The page's data was correct when it loaded, but other people may have booked since. The page can show what was true, but only the server knows what is true now.

Where Did the Focus Go?

After a successful booking, renderSessions() replaces every card, including the Book button that opened the dialog. When the dialog closes, the browser tries to return focus to that button, but it no longer exists, so focus is lost, and keyboard users are sent back to the top of the page.

When you replace the element that opened a dialog, move focus yourself to something sensible. Here, that is the new Cancel booking button on the same card:

const newButton = sessionList.querySelector(`[data-id="${currentSession.id}"][data-action="cancel"]`);
newButton.focus();

Try It

  1. Add the two lines above after the confirmation message in your submit listener.
  2. Book a session using only the keyboard, and check that focus lands on the new Cancel booking button.

Confirming an Action

Actions that cannot easily be undone, such as cancelling a booking or deleting something, should be confirmed first. A good confirmation dialog:

  • Says exactly what will happen, such as Your place on Styling With CSS will be given to someone else.
  • Labels its buttons with what they do, such as Keep my booking and Cancel booking, rather than OK and Cancel, which are confusing when the action itself is called cancel.
  • Puts the safe choice first, so that it receives focus when the dialog opens, and a user who presses Enter straight away does nothing harmful.

The close() method can be given a value, which is stored in the dialog's returnValue property. The dialog's close event then runs however the dialog was closed, and can check which button was used:

function openConfirm(session) {
    currentSession = session;
    confirmMessage.textContent = `Your place on "${session.title}" will be given to someone else.`;
    confirmDialog.returnValue = "";
    confirmDialog.showModal();
}

confirmKeep.addEventListener("click", () => {
    confirmDialog.close("keep");
});

confirmCancel.addEventListener("click", () => {
    confirmDialog.close("cancel");
});

confirmDialog.addEventListener("close", () => {
    if (confirmDialog.returnValue === "cancel") {
        // Cancel the booking
    }
});

Pressing Escape closes the dialog without changing returnValue, so it would still hold the value from the last time. This is why openConfirm resets it to an empty string before opening, so that Escape always counts as keeping the booking.

ℹ️ Info: In other tutorials, you may see dialog buttons placed inside a <form method="dialog">, which closes the dialog when a button is clicked and sets returnValue to the button's value, without any JavaScript. Calling close() with a value, as here, does the same job.

Check Your Page

Your click listener on the session list should now be similar to this:

sessionList.addEventListener("click", (event) => {
    const button = event.target.closest("button");
    if (!button) {
        return;
    }

    const session = sessions.find((item) => item.id === Number(button.dataset.id));

    if (button.dataset.action === "details") {
        openDetails(session);
    } else if (button.dataset.action === "book") {
        openBooking(session);
    } else if (button.dataset.action === "cancel") {
        openConfirm(session);
    }
});

Also check that:

  • Every dialog can be opened, used and closed with the keyboard only.
  • The booking form shows errors for an empty name and an invalid email address.
  • The submit button cannot be clicked twice while a booking is being sent.
  • A failed booking keeps the dialog open with a helpful message.
  • Focus never ends up lost at the top of the page after a dialog closes.
