Tutorial

In HTML lesson 10, you used attributes such as required and type="email" to let the browser check a form before sending it. In this lesson you will take control of that checking with JavaScript, known as validation, so that you can write your own rules, and give users clear, consistent and accessible feedback about exactly what needs fixing.

The starter code contains a booking form for the Beginners' Web Workshop. Complete each Try It section in the editor before moving on.


Why Validate With JavaScript?

The browser's built-in validation is a useful start, but it has limits:

  • Its messages look different in every browser, cannot be styled, and disappear after a few seconds.
  • It shows only one problem at a time, so a user with three mistakes must submit the form three times to find them all.
  • It can only check the rules that HTML attributes describe. Rules such as a student number is exactly eight digits, or this field cannot be only spaces, need code.

With JavaScript, you decide what the rules are, when they are checked, and how each problem is shown.

⚠️ Warning: Validation in the browser is there to help users, not to protect your data. Anyone can turn off JavaScript, or send data to a server without using your form at all. A website that stores form data must check it all again on the server. You will learn more about this in lesson 11.

Taking Over From the Browser

Adding the novalidate attribute to a <form> turns off the browser's own validation messages, so that they do not appear alongside yours:

<form id="booking-form" novalidate>

Keep the required and type attributes on the inputs, though. They still describe the fields correctly to assistive technology, mobile devices still show the right keyboard for each type, and they are a fallback if your JavaScript fails to load.

Then, as in JavaScript lesson 6, listen for the form's submit event, and call preventDefault() so that you can check the data before anything is sent:

bookingForm.addEventListener("submit", (event) => {
    event.preventDefault();
    // Validate the form here
});

Try It

  1. In the HTML tab, add novalidate to the form.
  2. In the JS tab, add the submit listener above.
  3. Submit the empty form. Nothing happens, because the browser's messages are off and you have not written your own yet.

Accessible Error Messages

Look at the starter HTML for the name field:

<label for="full-name">Full name</label>
<input type="text" id="full-name" required aria-describedby="full-name-error">
<p class="error-message" id="full-name-error"></p>

Each field has an empty paragraph for its error message, placed straight after it, so that the message appears right next to the problem. Two ARIA attributes make the message accessible:

  • aria-describedby links the input to the message. When a screen reader user moves to the input, they hear its label and then the text of the message, so they know what is wrong with it. The starter HTML already includes this. The student number field lists two ids, separated by a space, so its hint is read as well as its error.
  • aria-invalid="true" tells assistive technology that the field's value is not valid. Your code will add it when a field has a problem, and remove it when the problem is fixed.

Because every error paragraph's id is its input's id followed by -error, one pair of functions can show or clear the message for any field:

function showError(field, message) {
    const error = document.querySelector(`#${field.id}-error`);
    error.textContent = message;
    field.setAttribute("aria-invalid", "true");
}

function clearError(field) {
    const error = document.querySelector(`#${field.id}-error`);
    error.textContent = "";
    field.removeAttribute("aria-invalid");
}

The starter CSS styles any input with aria-invalid="true" with a thick red border. Using the ARIA attribute as the CSS selector, rather than a separate class, means the visual style and the information for screen readers can never disagree.

ℹ️ Info: Never show an error with colour alone. Some users cannot tell red from other colours. Each error here has a written message as well as the red border.

  1. Add the showError and clearError functions above.
  2. Test them at the bottom of your code with showError(fullNameInput, "Enter your full name");, and check the message and border appear. Then remove the test.

Writing the Rules

A tidy way to organise validation is a function that takes one field, checks its rules, and returns an error message, or an empty string if the field is valid. Before checking text, always trim() it, so that a value of only spaces counts as empty:

function validateField(field) {
    const value = field.value.trim();

    if (field === fullNameInput) {
        if (value === "") {
            return "Enter your full name";
        }
        if (value.length < 2) {
            return "Your name must be at least 2 characters";
        }
    }

    // ...rules for the other fields...

    return "";
}

Good error messages say exactly what to do, in plain words, without blaming the user. Compare Invalid input with Enter your email address in the correct format, like name@example.com. The second tells the user how to fix the problem.


Patterns With Regular Expressions

Some rules are about the shape of a value, such as exactly eight digits. JavaScript describes shapes with regular expressions: patterns written between two forward slashes. Their test() method returns true if a string matches:

const studentNumberPattern = /^\d{8}$/;

studentNumberPattern.test("12345678");   // true
studentNumberPattern.test("1234");       // false
studentNumberPattern.test("1234567a");   // false

Read the pattern one piece at a time:

  • ^ means the start of the string.
  • \d means any digit, from 0 to 9.
  • {8} means exactly eight of the thing before it.
  • $ means the end of the string.

Without ^ and $, the pattern would match eight digits anywhere in the string, so "abc12345678xyz" would pass.

A simple pattern for the shape of an email address is:

const emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

[^\s@]+ means one or more characters that are not a space or an @. So the whole pattern means: some characters, an @, some more characters, a dot, and some more characters, with no spaces anywhere.

💡 Tip: Do not try to write a perfect email pattern. Real email addresses can take surprising forms, and an over-strict pattern rejects real users. A pattern can only check the shape: the only way to know an address really works is to send an email to it.

    • Email: empty: Enter your email address. Not matching the pattern: Enter your email address in the correct format, like name@example.com.
    • Student number: empty: Enter your student number. Not matching the pattern: Your student number must be 8 digits.

Validating the Whole Form

With a function for one field, checking the whole form is a loop. The starter JavaScript has an array, fields, containing every field in the form. This function checks each one, shows or clears its message, and returns a list of the fields with problems:

function validateForm() {
    const invalidFields = [];

    fields.forEach((field) => {
        const message = validateField(field);
        if (message) {
            showError(field, message);
            invalidFields.push(field);
        } else {
            clearError(field);
        }
    });

    return invalidFields;
}

When the form is submitted with problems, two more things help users:

  • An error summary at the top of the form, saying how many problems there are. On a long form, this means users cannot miss that something is wrong.
  • Moving focus to the first field with a problem, with focus(). Keyboard users are taken straight to it, and screen reader users hear its label and its error message.
bookingForm.addEventListener("submit", (event) => {
    event.preventDefault();
    const invalidFields = validateForm();

    if (invalidFields.length > 0) {
        const count = invalidFields.length;
        errorSummary.textContent = count === 1
            ? "There is 1 problem with your booking. Please check the field marked below."
            : `There are ${count} problems with your booking. Please check the fields marked below.`;
        errorSummary.hidden = false;
        invalidFields[0].focus();
        return;
    }

    errorSummary.hidden = true;
    // The form is valid
});

Try It

  1. Add the validateForm function, and update your submit listener as above.
  2. Submit the empty form. Every required field shows its message, the summary appears, and focus moves to the name field.
  3. Fill in the name only, and submit again. The name's message disappears, the count goes down, and focus moves to the email field.
  4. Test the edge cases: a name of only spaces; an email without a dot after the @; a student number of seven digits, and of eight characters including a letter. Each should be rejected with the right message.

Checking as the User Types

Once a user has tried to submit, it helps to update each message as they fix it, so that they can see straight away when a field is right. Do not do this before they first submit, though: being told that an email address is wrong while you are still typing the first letter of it is annoying.

Instead of a listener on every field, one listener on the form can catch the input event from all of them, because events bubble up from an element to its parents. event.target is the field that changed:

let hasSubmitted = false;

bookingForm.addEventListener("input", (event) => {
    if (!hasSubmitted) {
        return;
    }
    const message = validateField(event.target);
    if (message) {
        showError(event.target, message);
    } else {
        clearError(event.target);
    }
});

Try It

  1. Add the hasSubmitted variable and the input listener above. In your submit listener, set hasSubmitted to true.
  2. Type in the email field before submitting. No message appears.
  3. Submit the form, then type a valid email address. The message disappears as soon as the address is valid.

A Character Counter

For a field with a length limit, a counter shows users how much space they have left before they reach it, which is friendlier than an error afterwards:

needsInput.addEventListener("input", () => {
    needsCount.textContent = `${needsInput.value.length} of 300 characters`;
});
ℹ️ Info: The counter does not have aria-live, because a screen reader announcing a new number after every key press would be overwhelming. It is part of the field's description through aria-describedby, so screen reader users hear it when they move to the field.

When the Form Is Valid

On a real website, a valid form's data would now be sent to a server. You will simulate this in the next lesson. For now, show a confirmation, then clear the form with the form's reset() method, which returns every field to its starting value:

const name = fullNameInput.value.trim();
const session = sessionSelect.options[sessionSelect.selectedIndex].text;

formStatus.textContent = `Thank you, ${name}. Your place on "${session}" is booked.`;
bookingForm.reset();
needsCount.textContent = "0 of 300 characters";
hasSubmitted = false;

sessionSelect.value would give the option's value, which is a short id. options[selectedIndex].text gives the text the user saw in the menu.

The confirmation uses textContent, so whatever the user typed is shown as plain text. If someone typed HTML tags into the name field, they would appear as text on the page, rather than being treated as HTML. You will see why this matters in lesson 11.

Try It

  1. Add the code above to your submit listener, after the summary is hidden.
  2. Fill in the form correctly and submit it. The confirmation appears, and the form is cleared.
  3. Type <b>Sam</b> as the name, and submit. The tags appear as text, and nothing is made bold.

The Constraint Validation API

Browsers also give JavaScript access to their own validation results through the Constraint Validation API. Every input has a validity object, describing which of its HTML rules it breaks, and a checkValidity() method that returns true if it breaks none:

emailInput.validity.valueMissing;   // true if required and empty
emailInput.validity.typeMismatch;   // true if not shaped like an email
emailInput.checkValidity();         // true if every HTML rule passes

This lets you keep simple rules in HTML attributes, such as required, minlength and pattern, while still writing your own messages and choosing how they are shown. Both approaches are fine. Writing the rules in JavaScript, as you have done, makes them easier to see and change in one place.


Check Your Page

Your submit listener should be similar to this:

bookingForm.addEventListener("submit", (event) => {
    event.preventDefault();
    hasSubmitted = true;
    formStatus.textContent = "";

    const invalidFields = validateForm();

    if (invalidFields.length > 0) {
        const count = invalidFields.length;
        errorSummary.textContent = count === 1
            ? "There is 1 problem with your booking. Please check the field marked below."
            : `There are ${count} problems with your booking. Please check the fields marked below.`;
        errorSummary.hidden = false;
        invalidFields[0].focus();
        return;
    }

    errorSummary.hidden = true;

    const name = fullNameInput.value.trim();
    const session = sessionSelect.options[sessionSelect.selectedIndex].text;
    formStatus.textContent = `Thank you, ${name}. Your place on "${session}" is booked.`;

    bookingForm.reset();
    needsCount.textContent = "0 of 300 characters";
    hasSubmitted = false;
});

Also check that every field shows the right message for each of its rules, that messages clear as fields are fixed after the first submit, and that you can complete the whole form using only the keyboard.
