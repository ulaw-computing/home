Requests and Responses

When a browser needs something from a server, such as a web page, an image or some data, it sends an HTTP request, and the server sends back an HTTP response. Every response includes a status code: a number that says whether the request worked. You will see these most often:

  • 200 OK: the request worked, and the response contains what was asked for.
  • 404 Not Found: there is nothing at that address.
  • 500 Internal Server Error: something went wrong on the server.

Codes in the 200s mean success, codes in the 400s mean a problem with the request, such as a wrong address, and codes in the 500s mean a problem on the server.


Using fetch

fetch() takes an address, sends a request to it, and returns a promise. When the server replies, the promise is fulfilled with a Response object:

async function loadSessions() {
    const response = await fetch("data/api/workshop-sessions.json");
    console.log(response.status);   // 200
    console.log(response.ok);       // true
}

The address here is a relative path, like the image paths you used in the HTML unit. It is relative to the page, so it loads the file from the same server.

The Response object describes the reply, but it does not contain the data yet. Reading the body of the response takes time too, so it has its own method that returns a promise. For JSON data, this is response.json(), which reads the body and converts it from JSON into JavaScript values, just like JSON.parse:

async function loadSessions() {
    const response = await fetch("data/api/workshop-sessions.json");
    const data = await response.json();
    console.log(data);
}

Loading data with fetch therefore always takes two awaits: one for the response to arrive, and one to read its data.

Understanding the Data's Shape

Before you can display data, you need to know its shape: what is an object, what is an array, and what each property is called. Logging the data and exploring it in the console, as you have just done, is always the first step. This file's data looks like this:

{
    "workshop": "Beginners' Web Workshop",
    "date": "2026-12-05",
    "venue": "The Learning Centre, Leeds",
    "sessions": [
        {
            "id": 1,
            "title": "How the Web Works",
            "level": "beginner",
            "time": "10:00",
            "speaker": "Amara Kofi",
            "room": "2.04",
            "spacesLeft": 12,
            "description": "What happens when you type a web address..."
        },
        ...
    ]
}

So data.workshop is the workshop's name, data.sessions is the array of sessions, and data.sessions[0].title is the first session's title. Most APIs wrap their data like this, with extra information around the array of results, so you will often need to reach inside the response to find the part you want.

Formatting a Date

The date in the data, "2026-12-05", is written in the international standard format, which computers can read reliably but people find less friendly. JavaScript's Date object can turn it into a readable date:

const date = new Date(data.date);
const readable = date.toLocaleDateString("en-GB", {
    weekday: "long",
    day: "numeric",
    month: "long",
    year: "numeric"
});
// "Saturday, 5 December 2026", or similar, depending on the browser

"en-GB" sets British English conventions, so the day comes before the month.

When a Request Fails

There are two quite different ways a request can fail, and fetch handles them differently:

  • No response at all. If the request cannot reach the server, for example because the user is offline or the address's domain does not exist, the promise from fetch is rejected.
  • A response that reports a problem. If the server replies with an error status, such as 404 or 500, the promise is still fulfilled, because a response did arrive. fetch does not treat a 404 as a failure.

This catches many developers out. To handle the second kind of failure, you must check the response yourself. The ok property is true for any status code from 200 to 299, and false otherwise. If it is false, you can throw an error, which stops the try block and jumps to catch, just like a rejected promise:

const response = await fetch("data/api/workshop-sessions.json");

if (!response.ok) {
    throw new Error(`The request failed with status ${response.status}.`);
}

const data = await response.json();

throw new Error(...) creates an error with a message, and hands it to the nearest catch block. Together, the check on response.ok and the try...catch handle both kinds of failure in one place.


Loading, Success and Failure

As you learned in the last lesson, every request needs three states. The starter HTML has a status message element, with role="status" so that screen reader users hear it change, and a Try again button, hidden by default:

async function loadSessions() {
    statusMessage.textContent = "Loading sessions…";
    retryButton.hidden = true;

    try {
        const response = await fetch("data/api/workshop-sessions.json");

        if (!response.ok) {
            throw new Error(`The request failed with status ${response.status}.`);
        }

        const data = await response.json();
        // ...display the data...
        statusMessage.textContent = `${data.sessions.length} sessions loaded.`;
    } catch (problem) {
        statusMessage.textContent = "Sorry, the sessions could not be loaded. Please try again.";
        retryButton.hidden = false;
        console.log(problem.message);
    }
}

The message shown to the user is plain and tells them what they can do. The technical detail, such as the status code, is logged for you, the developer, rather than shown to the user, who could do nothing with it.

Fetching From Your Own Computer

When you download your work and open the HTML file directly from your computer, the address bar starts with file://. For security reasons, browsers do not allow fetch to load files from file:// pages, so the request fails, even though the JSON file is right there in the folder.

To test pages that use fetch on your own computer, run them through a local web server: a small program that serves your folder at an address such as http://127.0.0.1:5500. The Live Server extension for Visual Studio Code does this with one click. Once your site is published, for example on GitHub Pages, it is served by a real web server, and fetch works normally.

async function loadSessions() {
