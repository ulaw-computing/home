Tutorial

A transition animates a change between two states, such as normal and hovered, and only runs when something changes. Some movement needs more than that: a loading spinner that turns continuously while data is fetched, cards that fade in one after another as a page loads, or a form field that shakes when its input is rejected. These use CSS animations, which can have any number of steps, run on their own, and repeat.

Keyframes

An animation is defined in two parts. First, an @keyframes rule describes what happens: the styles at different points, or keyframes, during the animation. It is given a name of your choice:

@keyframes spin {
    from {
        transform: rotate(0deg);
    }
    to {
        transform: rotate(360deg);
    }
}

from is the start of the animation and to is the end. For more steps, use percentages instead, where 0% is the start and 100% is the end:

@keyframes pulse {
    0%   { transform: scale(1); }
    50%  { transform: scale(1.15); }
    100% { transform: scale(1); }
}

The browser works out every frame in between, just as it does for a transition.


Applying an Animation

Second, the animation is applied to an element with the animation properties:

  • animation-name: the name of the @keyframes rule to use.
  • animation-duration: how long one run of the animation takes.
  • animation-timing-function: how the speed changes, using the same values as transitions, such as ease or linear.
  • animation-delay: how long to wait before starting.
  • animation-iteration-count: how many times to run, or infinite to run forever.
  • animation-direction: normal, reverse, or alternate, which runs forwards then backwards.
  • animation-fill-mode: which styles apply before the animation starts and after it ends. forwards keeps the final keyframe's styles, backwards applies the first keyframe's styles during any delay, and both does both.

They are usually written together with the animation shorthand. The name and duration are needed, and the rest are optional:

.spinner {
    animation: spin 1s linear infinite;
}
⚠️ Warning: The name in animation must match the name after @keyframes exactly, including capital letters. If they do not match, nothing happens, and the browser gives no warning.

A Loading Spinner

When a page is waiting for something, such as data from an API, the user needs to know that something is happening. A loading spinner is a common way to show this. It can be made from a single element: a circle with a border, where one side of the border is a different colour, spinning continuously.

.spinner {
    width: 40px;
    height: 40px;
    border: 4px solid #c5cae9;
    border-top-color: var(--colour-primary);
    border-radius: 50%;
    animation: spin 1s linear infinite;
}

linear keeps the speed constant, so the spinner turns smoothly instead of speeding up and slowing down on every turn.

A spinner is only a picture, so screen reader users need the same information in words. The starter HTML places the spinner inside an element with role="status", which, like aria-live="polite", announces its content when it changes, and includes visually hidden text that says Loading.

ℹ️ Info: The starter CSS has a .visually-hidden class, which hides text on screen while keeping it available to screen readers. This is a common pattern, used whenever information is shown visually, as with an icon or spinner, but also needs to be available as text.

Entrance Animations

A subtle animation as content appears can draw the eye to it, and make a page feel more polished. A common entrance is a fade-in-up: the content starts slightly lower and transparent, then moves up into place as it becomes solid.

@keyframes fade-in-up {
    from {
        opacity: 0;
        transform: translateY(12px);
    }
    to {
        opacity: 1;
        transform: translateY(0);
    }
}

.news-card {
    animation: fade-in-up 0.4s ease-out both;
}

The both fill mode matters here. During any delay, it applies the from keyframe, so the card is invisible until its animation starts, rather than appearing, disappearing and fading back in.

Staggering With a Custom Property

Cards that fade in one after another look smoother than cards that all appear at once. The delay for each card can be calculated from a custom property, set on each card in the HTML with a style attribute:

<article class="news-card" style="--i: 0">...</article>
<article class="news-card" style="--i: 1">...</article>
<article class="news-card" style="--i: 2">...</article>
.news-card {
    animation: fade-in-up 0.4s ease-out both;
    animation-delay: calc(var(--i) * 0.1s);
}

The first card waits 0s, the second 0.1s, and the third 0.2s. This is a rare case where a style attribute is appropriate: it does not set the card's appearance, only a number describing the card's position in the list, which the stylesheet then uses.

Triggering Animations With JavaScript

Like transitions, animations can be triggered by adding a class with JavaScript. A common use is a shake, which draws attention to a form field whose input has been rejected:

@keyframes shake {
    0%, 100% { transform: translateX(0); }
    20%, 60% { transform: translateX(-6px); }
    40%, 80% { transform: translateX(6px); }
}

.shake {
    animation: shake 0.4s ease-in-out;
}

Several keyframe selectors can share styles by separating them with commas, as with 0%, 100%.

There is one complication. An animation only runs when the class is added. If the class is still on the element from the last time, adding it again changes nothing, so the field would only ever shake once. The fix is to remove the class when the animation finishes, using the animationend event:

function shake(element) {
    element.classList.add("shake");
    element.addEventListener("animationend", () => {
        element.classList.remove("shake");
    }, { once: true });
}

The { once: true } option removes the listener automatically after it has run once, so a new listener is not added every time the field shakes.

⚠️ Warning: A shake on its own is not enough to tell users what is wrong. It cannot be seen by screen reader users, and does not explain the problem to anyone. Always show a clear error message as well. You will build accessible error messages properly in Lesson 9.

Letting Users Pause Animations

Continuous movement is distracting, and can make it very hard to concentrate for some people, including many with attention-related conditions. Accessibility guidelines require that any movement which starts automatically and lasts more than five seconds can be paused, stopped or hidden, unless it is essential, such as a loading spinner that only shows while something is loading.

The animation-play-state property pauses and resumes an animation: paused freezes it where it is, and running continues it.

.badge {
    animation: pulse 2s ease-in-out infinite;
}

body.paused .badge {
    animation-play-state: paused;
}

Reduced Motion

As with transitions, animations should respect the reduced motion setting. For most animations, the right response is to turn them off completely:

@media (prefers-reduced-motion: reduce) {
    .news-card,
    .badge,
    .shake {
        animation: none;
    }
}

With animation: none, the news cards simply appear, the badge stays still, and the field does not shake, but the error message still shows.

A loading spinner is different, because the movement itself tells the user that something is happening. A gentler alternative is to slow it down rather than stop it, or to replace it with a text message such as Loading….

⚠️ Warning: If an animation is removed with animation: none, the animationend event never fires, so a class added by JavaScript is never removed. For the shake, this does no harm, because the field does not move either way. If your JavaScript waits for animationend before doing something important, such as showing the next step, make sure it still happens when animations are turned off.

Animations or Transitions?

  • Use a transition when an element changes between two states because of something the user does, such as hovering, focusing or opening a panel.
  • Use an animation when the movement needs more than two steps, needs to repeat, or needs to run without the user doing anything, such as a spinner or an entrance.

The same principles from the last lesson apply to both: animate transform and opacity for smooth performance, keep the movement purposeful and short, and respect the reduced motion setting.

💡 Tip: Before adding an animation to your own projects, ask what job it does for the user. "It shows the data is loading", "it draws attention to new messages" and "it shows the input was rejected" are good reasons. "It looks nice" on its own is not, and a page with too many moving parts is tiring to use. Write the reason in a comment beside the animation.
