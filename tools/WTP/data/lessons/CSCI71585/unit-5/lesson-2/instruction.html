Tutorial

Movement on a web page can do a real job. A card that lifts slightly when you point at it tells you it can be clicked. A menu that slides in shows where it came from. A button that sinks when pressed confirms that it has been pressed. In this lesson you will learn the two CSS tools behind effects like these: transforms, which move, rotate and resize elements, and transitions, which animate a change smoothly instead of making it happen instantly.

The starter code contains a page of course modules, with cards, buttons, an accordion and a slide-in panel. As before, complete each Try It section in the editor before moving on.


Transforms

The transform property changes how an element is drawn: where it appears, its angle and its size. It takes one or more transform functions:

  • translate(x, y) moves an element. translateX() and translateY() move it along one direction only.
  • rotate(angle) turns it, with the angle in degrees, such as rotate(45deg). Positive angles turn clockwise.
  • scale(amount) resizes it. scale(1.1) makes it 10% larger, and scale(0.9) 10% smaller.
  • skew(angle) slants it. This is rarely useful on its own, but you will see it in decorative effects.
.card:hover {
    transform: translateY(-4px);   /* move up by 4px */
}

Transforms Do Not Affect the Layout

A transformed element is drawn in its new position, size or angle, but the space it takes up in the layout does not change. The elements around it stay exactly where they were, as if nothing had happened. This is different from changing margin, width or top, which push the surrounding content around.

This is what makes transforms so useful for effects: a card can grow or move on hover without shifting every other card on the page.

Combining Transforms

Several transform functions can go in one transform declaration, separated by spaces:

.card:hover {
    transform: translateY(-4px) scale(1.02);
}
⚠️ Warning: An element only has one transform property. If a second rule sets transform on the same element, it replaces the first completely, rather than adding to it. To combine transforms, list them all in one declaration. The order matters too: functions are applied from right to left, so rotate(45deg) translateX(50px) and translateX(50px) rotate(45deg) end up in different places.

transform-origin

Rotating and scaling happen around a point called the transform origin, which is the centre of the element by default. The transform-origin property moves it, using keywords or lengths:

.tilt {
    transform-origin: top left;   /* rotate around the top-left corner */
    transform: rotate(5deg);
}

Transitions

Without a transition, a change of style happens instantly. If a card moves up 4px on hover, it jumps there. A transition tells the browser to animate the change over a period of time instead. It has four parts:

  • transition-property: which property to animate, such as transform or background-color.
  • transition-duration: how long the change takes, in seconds (0.2s) or milliseconds (200ms).
  • transition-timing-function: how the speed changes during the transition. ease, the default, starts quickly and slows down at the end. linear keeps a constant speed, ease-in starts slowly, and ease-out slows down at the end.
  • transition-delay: how long to wait before starting.

They are usually written together with the transition shorthand:

.card {
    transition: transform 0.2s ease-out;
}

.card:hover {
    transform: translateY(-4px);
}

Several properties can be transitioned at once, separated by commas: transition: transform 0.2s ease-out, box-shadow 0.2s ease-out;.

⚠️ Warning: Put the transition on the element's normal state, not on :hover. A transition applies whenever the property changes, in either direction, so this makes the card animate up when the mouse arrives and back down when it leaves. If the transition were only on :hover, the card would snap back instantly.
ℹ️ Info: You will often see transition: all 0.3s, which animates every property that changes. It is quick to write, but it can animate things you did not intend, such as a colour change when the theme switches, and makes the browser do extra work. Name the properties you want to animate.

Try It

  1. Give the .module-card elements a transition of transform 0.2s ease-out, box-shadow 0.2s ease-out.
  2. Add a .module-card:hover rule with a transform of translateY(-4px) and a box-shadow of 0 8px 16px rgba(0, 0, 0, 0.15). Point at each card in the preview.
  3. Move the transition declaration into the :hover rule instead. Notice that the card now snaps back down when the mouse leaves. Move it back.

Keyboard Users and Touchscreens

A :hover effect only appears for mouse users. Keyboard users never hover, and touchscreens do not hover in the same way. Wherever a hover effect tells the user something, such as "this can be clicked", give keyboard users the same feedback when the element has focus.

The cards on this page contain a link. The :focus-within pseudo-class matches an element when anything inside it has focus, so the whole card can respond when its link is focused:

.module-card:hover,
.module-card:focus-within {
    transform: translateY(-4px);
    box-shadow: 0 8px 16px rgba(0, 0, 0, 0.15);
}

Try It

  1. Add .module-card:focus-within to your hover rule, as in the example above.
  2. Click on the preview, then press Tab to move through the card links. Each card lifts as its link receives focus.

Button Feedback

Small transforms make buttons feel responsive. Scaling a button down slightly while it is being pressed, with the :active pseudo-class, gives the impression of pressing a physical button:

.button {
    transition: background-color 0.15s ease-out, transform 0.1s ease-out;
}

.button:active {
    transform: scale(0.96);
}

Try It

  1. Give the .button elements the transition and :active rule from the example above. Click and hold a button to see it sink.

Using Custom Properties for Timing

As you learned in the last lesson, values that are used throughout a site belong in custom properties. Transition durations are a good example: a site where every transition uses the same speed feels consistent.

:root {
    --speed: 0.2s;
}

.module-card {
    transition: transform var(--speed) ease-out, box-shadow var(--speed) ease-out;
}

Try It

  1. Add --speed: 0.2s; to the :root rule in the starter CSS, and use var(--speed) in your card and button transitions.
  2. Change --speed to 1s to see every transition slow down at once, then change it back.

Transitions Triggered by JavaScript

A transition runs whenever a property changes, not only on hover. This means JavaScript can trigger one simply by adding or removing a class, in exactly the same way you toggled classes in the JavaScript unit. CSS handles the animation, and JavaScript only changes the state.

A Rotating Arrow

The page's accordion buttons already open and close their sections, using the JavaScript in the starter code, which updates aria-expanded. An arrow that rotates as the section opens shows the change of state clearly:

.accordion-arrow {
    display: inline-block;   /* transforms do not work on inline elements */
    transition: transform var(--speed) ease-out;
}

.accordion-button[aria-expanded="true"] .accordion-arrow {
    transform: rotate(90deg);
}

A Slide-In Panel

The starter page has a Help panel, which is fixed to the right-hand side of the screen. To hide it off-screen, move it its own full width to the right with translateX(100%). A percentage in translate is a percentage of the element's own size, so this always moves it exactly out of view, however wide it is. When JavaScript adds the open class, the panel slides back to translateX(0):

.help-panel {
    transform: translateX(100%);
    transition: transform var(--speed) ease-out;
}

.help-panel.open {
    transform: translateX(0);
}
⚠️ Warning: A panel moved off-screen with a transform is still part of the page. Keyboard users can still tab to the links inside it, and screen readers can still read it, even though it cannot be seen. The starter CSS also sets visibility: hidden on the closed panel, which removes it from the keyboard order and from screen readers, and switches it to visible when the panel opens. The starter CSS includes visibility in the transition list with a duration of 0s and a delay of var(--speed), so that when the panel closes, it stays visible until it has finished sliding out, then disappears. The .open rule sets transition-delay: 0s, so that when the panel opens, it becomes visible straight away, and focus can move into it.

Try It

  1. Add the two accordion arrow rules from the example above. Open and close each section, and check the arrow turns smoothly.
  2. The starter CSS already positions the help panel. Add transform: translateX(100%); to the .help-panel rule, and add transform to its transition list, which already contains visibility, so that it reads transition: transform var(--speed) ease-out, visibility 0s var(--speed);.
  3. Add the .help-panel.open rule with a transform of translateX(0).
  4. Click Help. The starter JavaScript adds the open class, and the panel slides in. Click Close to slide it out.

Performance: What to Animate

Every time a property changes, the browser may have to do three kinds of work: work out the layout (where everything goes), paint the pixels, and composite the painted layers together on screen. During an animation, this happens many times a second.

  • Animating width, height, margin or top changes the layout, so the browser has to recalculate the position of everything around the element on every frame. On slower devices, this makes animations stutter.
  • Animating transform and opacity does not change the layout, so the browser can usually move the element without recalculating anything else. These animations stay smooth, even on phones.
💡 Tip: Whenever possible, animate transform and opacity only. To make something grow, use scale() rather than changing its width. To move it, use translate() rather than changing top or left.

Motion With a Purpose

Every transition on this page does a job:

  • The lifting cards show that they can be clicked.
  • The sinking buttons confirm a press.
  • The rotating arrows show whether a section is open.
  • The sliding panel shows where the help came from and where it went.

Motion that does not do a job is decoration, and too much of it is distracting, slows the user down, and can make some people feel unwell. Keep transitions short, usually between 0.1 and 0.3 seconds, so that the page never feels slow to respond.

Reduced Motion

As you learned in JavaScript lesson 11, some people turn on a setting to reduce motion on their device, because movement on screen can cause dizziness or nausea. In CSS, the same setting is checked with a media query. Because the duration is a custom property, turning off every transition takes one rule:

@media (prefers-reduced-motion: reduce) {
    :root {
        --speed: 0s;
    }
}

The changes still happen, so the arrows still point the right way and the panel still opens, but instantly, without movement.

Try It

  1. Add the reduced motion media query from the example above, at the end of your CSS.
  2. If you can, turn on your device's reduced motion setting (on Windows, Settings > Accessibility > Visual effects > Animation effects; on a Mac, System Settings > Accessibility > Display > Reduce motion), and check that every change now happens instantly. Then turn it off again.

Check Your Page

Your main rules should be similar to these:

:root {
    --speed: 0.2s;
}

/* Cards lift to show they can be clicked, for mouse and keyboard users */
.module-card {
    transition: transform var(--speed) ease-out, box-shadow var(--speed) ease-out;
}

.module-card:hover,
.module-card:focus-within {
    transform: translateY(-4px);
    box-shadow: 0 8px 16px rgba(0, 0, 0, 0.15);
}

/* The panel slides in from the right; visibility keeps it out of the tab order when closed */
.help-panel {
    transform: translateX(100%);
    transition: transform var(--speed) ease-out, visibility 0s var(--speed);
}

.help-panel.open {
    transform: translateX(0);
}

@media (prefers-reduced-motion: reduce) {
    :root {
        --speed: 0s;
    }
}

Also check that the buttons sink when pressed, and the accordion arrows rotate as each section opens.
