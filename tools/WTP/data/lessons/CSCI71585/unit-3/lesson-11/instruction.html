Tutorial

More than half of all web traffic now comes from phones, and the same page might also be viewed on a tablet, a laptop or a huge desktop monitor. Responsive design means building one page that adapts to work well on every one of them, rather than separate sites for different devices. In this lesson you will learn the techniques that make this possible, and use them to fix a page that currently only works on a large screen.

The starter code contains a page for a coffee shop, designed for desktop screens only. The CSS tab already contains its styles, which you will change as you work through the lesson. As before, complete each Try It section in the editor before moving on.


Testing at Different Widths

To test a responsive page, you need to see it at different widths. In this platform, each preview behaves like its own browser window, so the page responds to the width of whichever preview it is shown in:

  • The pop-out preview is a separate browser window. You can resize it by dragging its edges, from as narrow as a phone to as wide as your screen. This is the main way you will test in this lesson.
  • The fullscreen preview is as wide as your screen, like a desktop browser.
  • The normal preview is somewhere in between, depending on the size of your screen, so it is less useful for testing small layouts.
💡 Tip: Keep the pop-out window open beside the editor for the whole lesson. It updates as you type, just like the normal preview.

The starter page has a dark bar across the top, which tells you which layout is currently being used. You will update it as you add each layout.

  1. Open the pop-out preview, and drag the edge of its window until it is roughly the width of a phone, so that the layout bar reads small. The page is wider than the window, so you have to scroll sideways, the photo is cut off, and the three columns of text are cramped.
  2. Open the fullscreen preview. On a wide screen, the page looks as it was designed to.

The Viewport Meta Tag

When smartphones first appeared, almost no websites were designed for small screens. To cope, phone browsers pretend to be a desktop screen, usually around 980px wide, and then shrink the whole page down to fit the phone. The result is a tiny, zoomed-out page that the user has to pinch to read.

The viewport <meta> tag tells the phone not to do this, and to use its real width instead:

<meta name="viewport" content="width=device-width, initial-scale=1">
  • width=device-width sets the width of the page to the width of the device's screen.
  • initial-scale=1 sets the starting zoom level to 100%.

Every responsive page needs this tag in its <head>, usually straight after the character encoding. Without it, none of the other techniques in this lesson work on a phone.

⚠️ Warning: You will sometimes see maximum-scale=1 or user-scalable=no added to the viewport tag. These stop users from zooming in, which makes the page unusable for many people with low vision. Never include them.
ℹ️ Info: Desktop browsers ignore the viewport tag, and so does this platform's preview, so adding it will not change anything you can see here. It makes all the difference on a real phone.

Try It

  1. In the HTML tab, add the viewport <meta> tag from the example above, directly below the charset line.

Fluid Layouts

The first rule of responsive design is to avoid fixed widths that are wider than a small screen. A container with width: 960px is 960px wide on every screen, so on a phone it overflows and the user has to scroll sideways. Instead, use widths that adapt:

  • max-width instead of width, so the element can shrink but does not grow too wide.
  • Percentages, fr units and flexible flex items, which share out the available space.
  • flex-wrap: wrap and auto-fit grids, from Lesson 9, which let items move onto new lines when there is not enough room.

Try It

  1. In the CSS tab, find the .container rule and change its width to max-width. In the narrow pop-out window, the sideways scrolling has gone, and the text fits the window.

Responsive Images

An image is displayed at its own size by default, so a 1200px photo is 1200px wide, even on a 375px phone. One rule fixes this for every image on the page:

img {
    max-width: 100%;
    height: auto;
}
  • max-width: 100% stops an image from ever being wider than its container. It can still be smaller, if the image itself is small.
  • height: auto keeps the image's proportions as its width shrinks. Without it, the height attribute in the HTML would keep it at its full height, squashing it.

Keep the width and height attributes on your images in the HTML, as you learned in the HTML unit. The browser uses them to work out the image's proportions and reserve the right amount of space, even while the CSS changes its size.

Try It

  1. Add the img rule from the example above. The photo now shrinks to fit the preview.

Media Queries

Fluid layouts and images get you a long way, but sometimes a page needs a different layout on different screens: three columns might work on a desktop, but on a phone, one column is far easier to read. A media query applies CSS only when a condition is true, such as the screen being at least a certain width:

@media (min-width: 600px) {
    .features {
        grid-template-columns: repeat(2, 1fr);
    }
}

The rules inside the braces work exactly like normal rules, but they only apply when the viewport is 600px wide or wider. Below that width, the browser ignores them completely.

  • min-width applies at that width and above.
  • max-width applies at that width and below.

The widths where the layout changes are called breakpoints.

⚠️ Warning: A media query does not add specificity. Its rules follow the normal cascade, so if a rule inside a media query has the same specificity as a rule outside it, whichever comes later wins. Always put your media queries after the normal rules they change, usually at the end of the stylesheet.
ℹ️ Info: Modern CSS also has a shorter range syntax for media queries, such as @media (width >= 600px), which means the same as (min-width: 600px). You will see both in other people's code.

Mobile-First Design

There are two ways to organise responsive CSS:

  • Desktop-first: write the styles for large screens, then use max-width media queries to undo and simplify them for smaller ones.
  • Mobile-first: write the styles for small screens first, then use min-width media queries to add to them as more space becomes available.

Mobile-first is the approach most developers recommend, for several reasons:

  • The small-screen layout is usually the simplest, often a single column, so it makes a natural starting point.
  • It is easier to add layout as space appears than to take it away.
  • Phones, which often have the slowest connections, get the simplest CSS, without lots of large-screen styles they then have to undo.
  • It makes you decide what really matters on the page, because there is only room for the essentials on a small screen.
/* Small screens: the default, with no media query */
.features {
    display: grid;
    grid-template-columns: 1fr;
    gap: 20px;
}

/* Medium screens and up */
@media (min-width: 600px) {
    .features {
        grid-template-columns: repeat(2, 1fr);
    }
}

/* Large screens and up */
@media (min-width: 900px) {
    .features {
        grid-template-columns: repeat(3, 1fr);
    }
}

Each media query only needs to contain what changes at that size. Everything else, such as the display and the gap, carries on from the rules before it.

Choosing Breakpoints

It is tempting to choose breakpoints that match particular devices, such as a popular phone or tablet. But there are thousands of different screen sizes, and new ones every year. Instead, choose breakpoints based on your content: start with a narrow window, slowly make it wider, and add a breakpoint wherever the layout starts to look wrong, such as when lines of text become too long or there is room for another column.

Try It

  1. Find the .features rule in the CSS tab. It is a desktop-first layout, with three columns on every screen. Change its grid-template-columns to 1fr, so it starts as a single column.
  2. At the end of the CSS, add the two media queries from the example above, for 600px and 900px.
  3. Inside the 600px media query, add a rule that changes the layout bar: body::before { content: "Layout: medium (600px and over)"; }. Inside the 900px media query, change it to "Layout: large (900px and over)".
  4. In the pop-out preview, slowly drag the edge of the window to make it wider, then narrower again. Watch the layout bar and the number of columns change at each breakpoint.

Responsive Navigation

Navigation menus often need to change too. On a small screen, a row of links may not fit, so stacking them in a column is simpler and gives each link plenty of room to tap.

Try It

  1. Find the nav ul rule. Add flex-direction: column; to it, so the links stack on small screens.
  2. Inside your 600px media query, add a rule that changes the nav ul back to flex-direction: row;.
  3. The header contains the shop's name and the navigation side by side, which is cramped on small screens. Change the header rule so its flex-direction is column by default, and row from 600px.

Responsive Text

Large headings that look great on a desktop can take up most of a phone screen. A simple mobile-first approach is to give headings a moderate size by default, and increase it at larger breakpoints.

Try It

  1. Change the .hero h1 font size to 2rem in its main rule.
  2. Inside the 900px media query, set it to 3rem.
ℹ️ Info: The clamp() function can make text grow smoothly between a minimum and a maximum size, such as font-size: clamp(2rem, 5vw, 3rem). Because the minimum and maximum are in rem, it avoids the zoom problem with plain vw sizes from Lesson 4.

Designing for Touch

On a touchscreen, there is no mouse pointer, so users tap with a fingertip, which is far less precise. Keep these points in mind:

  • Make targets large enough. Links and buttons should be at least around 44 by 44 pixels, including their padding, with space between them.
  • Do not rely on hover. Touchscreens cannot hover, so anything that only appears on :hover, such as a menu or extra information, is unreachable for touch users.

Other Media Features

ℹ️ Info: Media queries can test many conditions besides width. Two that are increasingly important are prefers-color-scheme, which tells you whether the user has chosen a dark theme on their device, and prefers-reduced-motion, which tells you the user wants to avoid animation. You will meet these again in later units. There is also @media print, which applies styles only when a page is printed, for example to hide the navigation.

Check Your Page

Your media queries, at the end of your CSS, should be similar to these:

@media (min-width: 600px) {
    body::before {
        content: "Layout: medium (600px and over)";
    }

    header,
    nav ul {
        flex-direction: row;
    }

    .features {
        grid-template-columns: repeat(2, 1fr);
    }
}

@media (min-width: 900px) {
    body::before {
        content: "Layout: large (900px and over)";
    }

    .features {
        grid-template-columns: repeat(3, 1fr);
    }

    .hero h1 {
        font-size: 3rem;
    }
}

Also check that:

  • The HTML has a viewport <meta> tag.
  • No sideways scrolling appears at any width, and the photo always fits.
  • The page has one column of features on small screens, two on medium screens and three on large ones.
  • The navigation and header stack on small screens, and sit in a row from 600px.
