Tutorial

By now you have written enough CSS to have run into a puzzle: two rules both style the same element, and only one of them wins. Perhaps a heading kept a colour you thought you had changed, or the internal stylesheet in Lesson 1 replaced a colour from your CSS tab. In this lesson you will learn exactly how the browser decides which style to use. Understanding this is the key to fixing CSS that "doesn't work".

The starter code contains a line-up page for a music festival, with some CSS already written. Several of its rules conflict on purpose. In many of the Try It sections, you will predict the result before checking it, so make a real prediction each time before you look at the preview.


The Cascade

The cascade is the set of rules the browser follows when several declarations try to set the same property on the same element. In simplified form, it compares them in this order, and stops as soon as one declaration wins:

  1. Importance: a declaration marked !important beats one that is not.
  2. Specificity: a declaration with a more specific selector beats a less specific one.
  3. Source order: if everything else is equal, the declaration that comes last wins.

The cascade works declaration by declaration, not rule by rule. If one rule sets a colour and a font, and another rule only sets a colour, the second rule can win the colour while the first rule still provides the font.

ℹ️ Info: The cascade also considers where styles come from. The browser's default stylesheet always loses to your styles, which is why your CSS can change the browser's default heading sizes and link colours.

Source Order

When two declarations have the same importance and the same specificity, the one that comes later wins. "Later" means later in the stylesheet, or in a stylesheet that is loaded later. This is what happened in Lesson 1: your internal <style> was placed after the <link> to your external stylesheet, so its rule won.

p {
    color: navy;
}

p {
    color: darkred;   /* This one wins: it comes later */
}

  1. Look at the starter CSS. There are two rules for .band, setting different colours. Predict which colour the band names in the line-up will be, then check the preview.
  2. Swap the order of the two .band rules, and check that the colour changes.

Specificity

Specificity measures how precisely a selector targets an element. The browser calculates it by counting three kinds of selector, written as three numbers, such as (0, 1, 2):

  1. IDs, such as #headliner.
  2. Classes, such as .band. Pseudo-classes, which you will meet in Lesson 8, count here too.
  3. Elements, such as p. Pseudo-elements, also in Lesson 8, count here too.

The universal selector, *, counts as nothing at all: (0, 0, 0).

Selector IDs Classes Elements Specificity
p 0 0 1 (0, 0, 1)
.band 0 1 0 (0, 1, 0)
li.band 0 1 1 (0, 1, 1)
.band.local 0 2 0 (0, 2, 0)
#headliner 1 0 0 (1, 0, 0)

.band.local, with no space, selects elements that have both classes.

To compare two selectors, compare the numbers from the left. The first column with a difference decides the winner, and the columns to its right do not matter. This means:

  • One ID beats any number of classes: (1, 0, 0) beats (0, 15, 0).
  • One class beats any number of elements: (0, 1, 0) beats (0, 0, 8).
⚠️ Warning: Specificity is not one number you add up. Ten classes do not equal one ID. Always compare the columns from left to right.

Source order only matters when specificity is exactly equal. A more specific selector wins even if it comes earlier in the stylesheet.

Try It

  1. The Saturday headliner is an <li> with class="band" and id="headliner". The starter CSS has a rule for #headliner near the top, before the .band rules. Predict which colour it will be, then check.
  2. Two of the bands have the classes band local. Below all the other band rules, add a rule for .local that sets the colour to darkgreen. Does it work? Why?
  3. Now move your .local rule to the very top of the CSS. It stops working. Change its selector to .band.local, and it works again even at the top. Use specificity to explain each result.

Inline Styles

Styles in a style attribute are not part of a selector at all, and they beat every selector in a stylesheet, including IDs. You can think of them as an extra column to the left of IDs. This is one of the main reasons to avoid them: once an inline style is set, no ordinary rule in your stylesheet can override it.

Try It

  1. In the HTML, add style="color: hotpink;" to the headliner's <li>. It overrides the ID rule.
  2. Remove the inline style.

!important

Adding !important to the end of a declaration makes it beat every normal declaration, whatever their specificity, including inline styles:

.band {
    color: orange !important;
}
⚠️ Warning: Avoid !important. It does not fix the underlying problem; it just wins the argument by force. The only way to override an !important declaration is with another, more specific !important declaration, and stylesheets that rely on it quickly become a mess that nobody can safely change. If a rule is not applying, find out why with the steps at the end of this lesson, and fix the selector or the order instead.

Try It

  1. Add !important to the colour in one of your .band rules. Notice that every band changes, including the headliner, overriding the ID.
  2. Remove the !important.

Inheritance

Some properties are inherited: when you set them on an element, its children and other descendants use the same value, unless something sets them directly. This is why setting font-family on the body in Lesson 4 changed the font of the whole page.

As a general rule:

  • Text properties are inherited, such as color, font-family, font-size, font-weight, line-height, text-align and letter-spacing. It makes sense for text inside an element to look like the text around it.
  • Box properties are not inherited, such as background-color, border, padding, margin and width. It would make little sense for every paragraph inside a bordered box to have its own border too.
ℹ️ Info: background-color can look inherited, because a child's background is transparent by default, so you see the parent's background through it. The child does not actually have a background colour of its own.

Inherited Values Always Lose

An inherited value has no specificity at all. Any rule that targets an element directly beats a value it would otherwise inherit, even a rule with the lowest specificity, and even the browser's default stylesheet.

This explains a very common puzzle: if you set color on the body, links do not change colour. The browser's default stylesheet has a rule that targets <a> elements directly, making them blue, and a direct rule always beats an inherited value.

The inherit keyword tells an element to use its parent's value for a property, even if something else is targeting it:

a {
    color: inherit;
}

Try It

  1. Give the .stage sections a color of midnightblue. Notice that the headings and the paragraph inside them change, because color is inherited. The band names do not change, because the .band rules target them directly.
  2. The link to the stage map inside the first stage did not change colour either. Explain why, then add a rule that makes links inside a .stage inherit their colour, using the selector .stage a. You will learn how this selector works in Lesson 8.
  3. Give the .stage sections a border of 2px solid midnightblue. You will learn about borders in the next lesson. Notice that only the sections themselves have a border, not the headings and lists inside them, because border is not inherited.

When a Style Does Not Apply

When a declaration is not working, check these things, in this order:

  1. Is the CSS valid? Check the spelling of the property and value, and look for missing colons, semicolons and braces. Invalid declarations are silently ignored.
  2. Does the selector match the element? Check the spelling and case of class names against the HTML.
  3. Is a more specific rule winning? Look for other rules that target the same element with IDs or more classes.
  4. Is a later rule winning? Look further down the stylesheet for rules with the same specificity.
  5. Is the value only inherited? If the element is being targeted directly by another rule, including a browser default, the inherited value loses.
💡 Tip: Keep your selectors as simple and low in specificity as possible, mostly single classes. When every rule has similar specificity, source order does most of the work, and your CSS stays easy to predict and to override when you need to.

Check Your Page

Check that:

  • There is no inline style and no !important left in your code.
  • The local bands are dark green, using .band.local.
  • The link inside the first stage is the same colour as the text around it.
  • Only the stage sections have a border.
