Tutorial

So far, every element you have styled has stayed in the place the browser gave it, one block after another down the page. This arrangement is called the normal flow, and it is the right choice for most content. Sometimes, though, you need an element somewhere else: a label in the corner of a photo, a header that stays at the top while the page scrolls, or a button that is always visible. The position property makes this possible.

The starter code contains a listing for a holiday cottage. The page is long on purpose, so that you can scroll the preview. As before, complete each Try It section in the editor before moving on.


The position Property

position has five values. Every value except static lets you move the element with four offset properties: top, right, bottom and left. Each one sets the distance from that edge of a reference point. Which reference point depends on the position value.

  • static: the default. The element stays in the normal flow, and the offsets have no effect.
  • relative: moved relative to its normal position.
  • absolute: placed relative to its nearest positioned ancestor.
  • fixed: placed relative to the browser window.
  • sticky: stays in the normal flow until the page scrolls, then sticks in place.

An element with any value except static is called a positioned element.


Relative Positioning

An element with position: relative is moved away from where it would normally be. top: 10px moves it 10px down, away from the top of its normal position, and left: 20px moves it 20px to the right.

.nudge {
    position: relative;
    top: 10px;
    left: 20px;
}

The important thing about relative positioning is that the element's original space is kept. Everything around it stays exactly where it was, as if the element had not moved, so a moved element can overlap its neighbours.

💡 Tip: Relative positioning is rarely used to move things. Its main use is as a reference point for absolutely positioned elements inside it, which you will see next. A position: relative with no offsets does not move the element at all.

  1. In the Practice Area at the bottom of the page, there are three boxes. Give the middle one, .box-two, a position of relative, a top of 20px and a left of 40px.
  2. Notice that the box overlaps the box below it, and that the gap where it used to be is still there.

Absolute Positioning

An element with position: absolute is removed from the normal flow completely. The other elements close up the space as if it were not there, and it is placed using the offsets, measured from the edges of its containing block:

  • The containing block is its nearest ancestor that is positioned, meaning an ancestor with any position value other than static.
  • If no ancestor is positioned, it is placed relative to the page itself.

So the usual pattern is to give the parent position: relative, which does not move it, and the child position: absolute:

.photo-card {
    position: relative;   /* the reference point */
}

.label {
    position: absolute;
    top: 10px;
    left: 10px;           /* 10px from the top-left corner of .photo-card */
}

Absolute positioning is ideal for small items that sit on top of something else, such as labels on images, close buttons in the corner of a box, or notification counts on an icon.

Try It

  1. The cottage photo is inside a <figure class="listing-photo">, along with a <span class="badge"> saying Special offer. Give the .badge a position of absolute, a top of 10px and a left of 10px.
  2. The badge jumps to the top-left corner of the whole page, not of the photo, because none of its ancestors are positioned yet.
  3. Give the .listing-photo a position of relative. The badge moves into the corner of the photo.

Fixed Positioning

An element with position: fixed is also removed from the normal flow, but it is placed relative to the viewport, the visible area of the browser window. It stays in exactly the same place on screen, however far the page is scrolled.

.help-button {
    position: fixed;
    bottom: 20px;
    right: 20px;
}
⚠️ Warning: Fixed elements always cover whatever is behind them. Keep them small, and think about small screens and zoomed-in pages, where a large fixed element can hide much of the content. Fixed banners that cannot be closed are a common accessibility complaint.

Try It

  1. Give the .book-button link a position of fixed, a bottom of 20px and a right of 20px.
  2. Scroll the preview. The button stays in the bottom-right corner the whole time.

Sticky Positioning

An element with position: sticky is a hybrid. It stays in the normal flow, like a static element, until the page scrolls far enough for it to reach the offset you set. It then sticks at that position, like a fixed element, until its parent scrolls out of view.

header {
    position: sticky;
    top: 0;
}

A sticky element needs at least one offset, usually top, to know where to stick. It only sticks within its parent element, so a sticky heading inside a short section stops sticking when the section ends.

💡 Tip: Give sticky and fixed elements a background-color. By default, their background is transparent, so the content scrolling underneath them shows through.

Try It

  1. Give the page header a position of sticky and a top of 0.
  2. Scroll the preview. The header sticks to the top, but the text scrolling underneath it shows through.
  3. Give the header a background-color of white.

Stacking and z-index

When positioned elements overlap, the browser has to decide which one appears in front. By default, a positioned element that comes later in the HTML is drawn on top of one that comes earlier, and positioned elements are drawn on top of elements in the normal flow.

The z-index property changes this order. It takes a whole number, and an element with a higher z-index appears in front of one with a lower value. The name comes from the z-axis, the imaginary axis that points out of the screen towards you.

header {
    position: sticky;
    top: 0;
    z-index: 10;
}
⚠️ Warning: z-index only works on positioned elements (and on flex and grid items, which you will meet in Lesson 9). On a static element, it does nothing at all. If a z-index is not working, check the element's position first.
ℹ️ Info: Some properties, including a positioned element's z-index and opacity below 1, create a new stacking context: a separate layer whose children are stacked only against each other. A child can never appear in front of something outside its parent's layer, however high its own z-index is. If a very high z-index still does not bring an element to the front, this is usually why.
💡 Tip: Use small, spaced-out values such as 1, 10 and 100, rather than huge numbers like 99999. Spacing them out leaves room to add layers in between later.

Try It

  1. Scroll the preview slowly so that the photo passes under the sticky header. The badge appears in front of the header, because both are positioned and the badge comes later in the HTML.
  2. Give the header a z-index of 10. The badge now passes behind it.

A Note on float

In older code, you will often see the float property, such as float: left. It was designed to let text wrap around an image, as in a newspaper, and before flexbox and grid existed, developers used it to build entire page layouts. It still works for wrapping text around images, but for layout it has been completely replaced by the tools in Lesson 9, which are far easier and more reliable. You do not need to use it, but you should recognise it.
