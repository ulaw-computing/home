Tutorial

In this final lesson, you will bring together everything from this unit to style a complete page from scratch, then check your CSS with the same kind of validator you used for HTML.

The page is the Beginners' Web Workshop page from the end of the HTML unit, so its HTML is already written for you in the starter code. As in that lesson, there are no step-by-step instructions. Instead, you have a brief and a checklist. If you are unsure how to do something, look back at the relevant lesson.


The Brief

The workshop organisers want their page to look friendly, modern and welcoming to complete beginners. It must be easy to read, work well on phones, and be usable by everyone, including keyboard and screen reader users.

The design is up to you. The page should include the following.


Foundations (Lessons 1, 2 and 6)

  • All of your CSS in the CSS tab, with no inline styles or <style> elements.
  • Comments labelling each section of your stylesheet.
  • The box-sizing: border-box rule at the top.
  • Mostly class and element selectors, with no ID selectors used for styling. You may add classes to the HTML wherever you need them.

Colour and Type (Lessons 3 and 4)

  • A colour scheme of two or three main colours, plus neutrals such as white and grey.
  • Text and background colours that pass the WCAG contrast ratio for their text size.
  • At least one Google Font, with a suitable font stack.
  • Font sizes in rem, and a comfortable line-height for body text.
  • A background colour or image on at least one section.

Boxes and Layout (Lessons 6, 7 and 9)

  • The page content centred, with a max-width that keeps lines of text a readable length.
  • Consistent spacing, using padding and margins.
  • A header laid out with flexbox, with the site name and the navigation side by side on larger screens.
  • At least one layout using grid, such as placing the venue's photo beside its details on larger screens.
  • A sticky header, with a background colour and a suitable z-index.

Selectors and States (Lesson 8)

  • Styles for all five link states, in the correct order.
  • A clearly visible focus style on every link and form control.
  • At least one combinator, and at least one pseudo-element.

Components (Lesson 10)

  • A horizontal navigation menu with no bullets or indent.
  • A schedule table with collapsed borders, padded cells, styled header cells and striped rows.
  • A form with labels above their fields, inherited fonts, clearly visible field borders, and a styled button with hover and active states.

Responsive Design (Lesson 11)

  • Mobile-first CSS, with at least one min-width media query at the end of the stylesheet.
  • No sideways scrolling at any width, and images that never overflow their containers.
  • A layout that changes sensibly between small and large screens.

Plan Before You Build

Before writing any CSS, make some design decisions, and note them as comments at the top of your stylesheet:

/*
   Colours:  primary #00695c, accent #ffb300, text #333, background #fafafa
   Fonts:    headings Merriweather, body Open Sans
   Spacing:  small 8px, medium 16px, large 32px
   Breakpoint: 700px
*/

Using a small, fixed set of colours, fonts and spacing values throughout makes a design look consistent and deliberate. Check your colour pairs in the WebAIM Contrast Checker before you start.

💡 Tip: Style the page in stages, and check the preview after each one, at both a narrow and a wide width:
  1. The basics: box-sizing, fonts, colours and the main container.
  2. The header and navigation.
  3. Each section of the page, one at a time.
  4. The table and the form.
  5. The media queries for larger screens.
  6. Link states and focus styles.

Validating Your CSS

As you have seen throughout this unit, the browser silently ignores CSS it does not understand. A misspelt property, a missing semicolon or an invalid value simply stops working, with no error message. A validator checks your CSS against the rules of the language and lists every problem it finds.

The standard tool is the W3C CSS Validation Service. Like the HTML validator, it can check code pasted straight into it.

Try It

  1. When your styling is complete, select all of the code in the CSS tab and copy it.
  2. Open the W3C CSS Validation Service's "By direct input" page.
  3. Paste your CSS into the box and click Check.
  4. If it shows "Congratulations! No Error Found.", your CSS is valid. Otherwise, work through the errors as described below until it is.

Reading Validator Results

The validator lists errors first, each with a line number, the selector it was found in and a description. Below the errors, it shows your CSS as it understood it.

💡 Tip: As with HTML, fix errors from the top down, and check again after each fix. A missing closing brace makes the validator misread everything after it, so one small mistake can produce a long list of errors.
ℹ️ Info: The validator can be slower than browsers to recognise very new CSS features. If it reports an error on a property you have checked on MDN and know is valid, such as accent-color, you can treat it as a warning rather than a real error.
⚠️ Warning: Valid CSS is not the same as good CSS. The validator checks the syntax, but it cannot tell you whether your text has enough contrast, whether your focus styles are visible, or whether your layout works on a phone. Check those yourself, using the checklist below.

Try It: Break It on Purpose

Make each change below, validate your CSS, read the message, then undo the change:

  1. Change one color property to colour.
  2. Change one colour value to an invalid one, such as color: 12px;.
  3. Delete the semicolon between two declarations.
  4. Add a // comment line above a rule.
  5. Delete the closing brace of one rule near the top of your stylesheet.

Notice that the first four each produce a clear error on the right line, but the missing brace may produce errors in rules that are actually correct.


Check Your Page

Your page is complete when:

  • Every item in the brief is included.
  • The W3C CSS validator reports no errors.
  • Every text and background colour pair passes its contrast check.
  • You can reach every link and form control by pressing Tab, and you can always see which one has focus.
  • The page works with no sideways scrolling in a narrow pop-out preview, and makes good use of the space in the fullscreen preview.
  • Submitting the form shows the data that would be sent.

Make sure you download your work using the Download button. Together with your HTML from the previous unit, you now have a complete, styled, responsive page to use as a reference.


Unit Summary

In this unit, you have learned to:

  • Write CSS rules, and add CSS to a page with an external stylesheet.
  • Select elements by type, class, ID, relationship, state and position.
  • Use colours in several formats, and check their contrast.
  • Choose and size fonts, and style text for readability.
  • Predict which rule wins using the cascade, specificity and inheritance.
  • Control the size and spacing of elements with the box model.
  • Position elements, and control how they stack.
  • Build layouts with flexbox and grid.
  • Style accessible navigation menus, tables and forms.
  • Make pages responsive with fluid layouts, flexible images and media queries.
  • Check your CSS with a validator.
