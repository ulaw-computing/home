Tutorial

Lists, tables and forms appear on almost every website, and the browser's default styles for them are plain and often hard to use. In this lesson you will bring together selectors, pseudo-classes, the box model and flexbox to turn each of them into a polished, accessible component: a navigation menu, a readable data table, and a clear, comfortable form.

The starter code contains a page for a computing society, with a navigation list, an events table and a sign-up form like the one you built in the HTML unit. As before, complete each Try It section in the editor before moving on.


Lists

List Markers

The bullet or number at the start of each list item is called its marker. The list-style-type property changes it:

  • For unordered lists: disc (the default), circle and square.
  • For ordered lists: decimal (the default), lower-alpha, upper-alpha, lower-roman and upper-roman.
  • For any list: none, which removes the markers completely.

The list-style shorthand can set the type, along with the position of the marker and an image to use instead of it. The ::marker pseudo-element lets you style the markers themselves, such as their colour:

.rules {
    list-style-type: square;
}

.rules li::marker {
    color: teal;
}
ℹ️ Info: Changing the list style in CSS does not change its meaning. If the numbering is part of the content, such as steps in a process, use an <ol> in the HTML, even if the numbers are styled differently.

Try It

  1. The Society Rules list is an ordered list. Change its markers to lowercase letters, using the .rules class.
  2. Make the markers teal using ::marker.

Building a Navigation Menu

Navigation links are usually written as a list, since they are a list of places to go. Turning that list into a horizontal menu takes three steps:

  1. Remove the markers and indent. Browsers indent lists using padding on the <ul>, and add margin above and below it. Removing the markers alone leaves the indent behind, so remove all three.
  2. Lay out the items in a row, using flexbox.
  3. Style the links as clear, clickable areas.
nav ul {
    list-style: none;
    margin: 0;
    padding: 0;
    display: flex;
    gap: 4px;
}

nav a {
    display: block;
    padding: 10px 16px;
}

Making each link display: block, with padding, means the whole padded area can be clicked, not just the words. Large click targets are easier for everyone to use, especially on touchscreens and for people with limited motor control.

Try It

  1. Turn the nav ul into a horizontal menu, using the example above.
  2. Style the nav a links with a color of white, no underline, and display: block with padding.
  3. Give the links a background-color of #00695c when they are hovered over or focused, by grouping nav a:hover and nav a:focus in one rule.
  4. The link to the current page has aria-current="page" in the HTML, which tells screen readers which page the user is on. Style it differently from the others, using the selector nav a[aria-current="page"]: give it a border-bottom of 3px solid white.
ℹ️ Info: [aria-current="page"] is an attribute selector: it selects elements with a particular attribute and value. Attribute selectors count as classes in specificity. Styling the current page this way means the visual style and the screen reader information always match.

Tables

A data table's job is to make information easy to scan and compare. Good table styles usually include:

  • Clear borders or dividers between rows.
  • Padding in the cells, so the data is not cramped.
  • Distinct header cells, so it is clear what each column contains.
  • Consistent alignment. Text is easiest to read aligned left, and numbers are easiest to compare aligned right.

Borders

If you give table cells a border, each cell gets its own border, with a small gap between them, so the table is full of double lines. border-collapse: collapse on the table merges neighbouring borders into single lines:

table {
    border-collapse: collapse;
    width: 100%;
}

th,
td {
    padding: 8px 12px;
    border-bottom: 1px solid #ddd;
    text-align: left;
}

Striped Rows

Striped rows, often called zebra striping, help the reader's eye follow a row across a wide table. The :nth-child() pseudo-class from Lesson 8 does this without any extra classes:

tbody tr:nth-child(even) {
    background-color: #f4f4f4;
}

Try It

  1. Give the table a width of 100% and border-collapse: collapse.
  2. Give the th and td cells padding, a bottom border, and left-aligned text, as in the example above.
  3. Give the thead th cells a background-color of teal and a color of white.
  4. Add striped rows to the tbody.
  5. The last column contains prices. Right-align it using the .price class, which is already on the cells in that column. Check that its heading is right-aligned too, so it lines up with the numbers.
  6. Style the table's caption with text-align: left, font-weight: bold and a padding of 8px 0.
💡 Tip: Wide tables can overflow narrow screens. A common fix is to wrap the table in a <div> with overflow-x: auto, so the table scrolls sideways inside its box instead of breaking the page layout. You will look at small screens properly in the next lesson.

Forms

Forms are where users do the most work on a website, so clear, comfortable forms make a real difference. Good form styles usually include:

  • Labels above their fields, which are easiest to scan, especially on small screens.
  • Fields that are large enough to read and to tap.
  • Clear focus styles, so users always know which field they are typing in.
  • A button that looks clickable, with clear hover and focus states.

Fonts in Form Controls

Form controls, including inputs, dropdowns, text areas and buttons, do not inherit fonts by default. Browsers give them their own small system font, so they look out of place next to the rest of your page. The fix is to tell them to inherit:

input,
select,
textarea,
button {
    font: inherit;
}

Try It

  1. Add the font: inherit rule from the example above. Notice that the text in the form fields and button now matches the rest of the page.

Laying Out Fields

In the form, each label and its field are wrapped in a <div class="field">. Making each one a flex column puts the label above the field, with a small gap:

.field {
    display: flex;
    flex-direction: column;
    gap: 4px;
    margin-bottom: 16px;
}

Fields are then given a comfortable size with padding, a clear border, and a width that fills the form:

input[type="text"],
input[type="email"],
select,
textarea {
    padding: 8px;
    border: 1px solid #767676;
    border-radius: 4px;
}
⚠️ Warning: Light grey borders are fashionable, but if a field's border is too faint, users cannot see where to type. Accessibility guidelines require the edges of form controls to have a contrast ratio of at least 3:1 against the background. #767676 passes on white.

Try It

  1. Add the .field rule from the example above. Each label now sits above its field.
  2. Style the text inputs, the dropdown and the text area as in the second example.
  3. The form is inside a .signup element. Give it a max-width of 500px, so the fields do not stretch across very wide screens.

Focus Styles for Fields

As with links, every form control must have a visible focus style. A thick outline in an accent colour is clear and simple:

input:focus,
select:focus,
textarea:focus,
button:focus {
    outline: 3px solid darkorange;
    outline-offset: 2px;
}

Checkboxes and Radio Buttons

Checkboxes and radio buttons are difficult to restyle completely, but the accent-color property changes their colour in one line, while keeping them fully accessible:

input[type="checkbox"],
input[type="radio"] {
    accent-color: teal;
}

Fieldsets

Fieldsets have a default border and padding from the browser. You can style them like any other box, and the legend like any other text.

Try It

  1. Add the focus rule from the example above. Click into each field, and press Tab to move through the form, checking that you can always see which control has focus.
  2. Give the checkboxes and radio buttons an accent-color of teal, then tick a box to see it.
  3. Give the fieldset elements a border of 1px solid #ccc, a border-radius of 4px and a margin-bottom of 16px, and make each legend bold.

Buttons

A button should look clickable, and should respond when the user interacts with it:

button {
    padding: 10px 24px;
    background-color: teal;
    color: white;
    border: none;
    border-radius: 4px;
    cursor: pointer;
}

button:hover {
    background-color: #00695c;
}

The cursor property changes the mouse pointer. pointer shows the pointing hand that users expect over things they can click.

Try It

  1. Style the button as in the example above, including its hover state.
  2. Add a button:active rule with a background-color of #004d40, so the button darkens further while it is being clicked.
  3. Fill in the form and click Sign up. The platform shows the data that would be sent, as in the HTML unit.

What You Cannot Style

ℹ️ Info: Some parts of form controls are drawn by the browser or the operating system, and CSS can only change them a little, or not at all. The open list of a dropdown, the calendar of a date picker and the button of a file upload field are the most common examples. The appearance: none property removes a control's built-in styling so you can style it from scratch, but rebuilding a control completely is a lot of work, and it is easy to make it less accessible in the process. For most forms, styling the parts you can, as in this lesson, is the right choice.
ℹ️ Info: The :invalid pseudo-class selects form fields whose current value fails their checks, such as a required field that is empty. It applies as soon as the page loads, so every empty required field is "invalid" before the user has even started. The newer :user-invalid pseudo-class only applies after the user has interacted with the field, which is usually what you want.

Check Your Page

Check that:

  • The navigation is a horizontal menu, with no bullets or indent, a clear hover and focus style, and a marker on the current page.
  • The rules list uses teal lowercase letters.
  • The table has single-line row dividers, padded cells, a teal header, striped rows and right-aligned prices.
  • Every label sits above its field, and every control has a visible focus style.
  • The form uses the same font as the rest of the page.
  • The button changes when hovered over and clicked.
