Tutorial

To a browser, every element on a page is a rectangular box. Headings, paragraphs, images, links, even single words in a <span>: all of them are boxes. The box model describes how the size of each box is worked out, and how much space there is inside and around it. It is the foundation of every layout you will build, and understanding it explains most of the spacing problems you will ever meet in CSS.

First, though, you need to know about the display property, because the box model works differently for different kinds of box. The starter code contains a team page with profile cards. As before, complete each Try It section in the editor before moving on.


The display Property

In the HTML unit, you learned that elements are either block or inline by default. The display property controls this, and CSS can change it for any element. The most common values are:

  • block: starts on a new line and fills the full width available. The default for elements such as <p>, <div> and <h1>.
  • inline: sits within a line of text and is only as wide as its content. The default for elements such as <a>, <span> and <strong>.
  • inline-block: sits within a line like an inline element, but can be sized and spaced like a block. This is useful for things like buttons that sit side by side.
  • none: hides the element completely.
ℹ️ Info: display has two more important values, flex and grid, which turn an element into a layout container. You will learn about both in Lesson 9.

Hiding Elements

display: none removes an element from the page as if it were not in the HTML at all: it takes up no space, and screen readers ignore it. This is different from visibility: hidden, which makes an element invisible but leaves an empty space where it was.

⚠️ Warning: Hiding something with CSS does not remove it from the page's code. Anyone can view the HTML source and read hidden content, so never use CSS to hide anything private.

The Box Model

Every box is made of four layers, from the inside out:

┌──────────────────────────────────┐
│ margin                           │
│  ┌────────────────────────────┐  │
│  │ border                     │  │
│  │  ┌──────────────────────┐  │  │
│  │  │ padding              │  │  │
│  │  │  ┌────────────────┐  │  │  │
│  │  │  │    content     │  │  │  │
│  │  │  └────────────────┘  │  │  │
│  │  └──────────────────────┘  │  │
│  └────────────────────────────┘  │
└──────────────────────────────────┘
  • Content: the text, image or other content itself.
  • Padding: space inside the box, between the content and the border. The element's background colour fills the padding.
  • Border: a line around the padding.
  • Margin: space outside the box, between its border and the boxes around it. The margin is always transparent.
💡 Tip: To decide between padding and margin, ask whether the space should be inside the box, with its background colour, or outside it, separating it from other boxes. Space around text inside a coloured card is padding. Space between two cards is margin.

Width and Height

The width and height properties set the size of the box's content area. You can use any of the units from Lesson 4.

A block element is as wide as its parent by default, and as tall as its content. In most cases, you should let the content decide the height, because you rarely know how much text an element will contain, or how big the user's text will be.

Two variations are often more useful than fixed sizes:

  • max-width sets a maximum width. The element is as wide as it can be, up to that limit, so it shrinks on small screens but does not stretch too wide on large ones. Lines of text are easiest to read at around 60 to 75 characters long, so max-width is ideal for blocks of text.
  • min-height sets a minimum height. The element is at least that tall, but can still grow if its content needs more room.

Padding

Padding can be set on each side separately, with padding-top, padding-right, padding-bottom and padding-left, or all at once with the padding shorthand. The shorthand accepts one to four values:

padding: 20px;                  /* all four sides */
padding: 10px 20px;             /* top and bottom, left and right */
padding: 10px 20px 30px;        /* top, left and right, bottom */
padding: 10px 20px 30px 40px;   /* top, right, bottom, left */

With four values, the order goes clockwise from the top: top, right, bottom, left. The same pattern works for margin.

💡 Tip: To remember the four-value order, think of a clock starting at 12 and going round, or remember the word TRouBLe: Top, Right, Bottom, Left.

Try It

  1. Give each .card a padding of 20px. The text moves away from the edges of the card.
  2. Give the .card h3 headings a padding of 0 0 10px, to add space only below them.

Borders

A border needs three things: a width, a style and a colour. They are usually set together with the border shorthand:

border: 1px solid #ccc;
  • Common styles are solid, dashed, dotted and double.
  • Each side can be set separately, such as border-bottom: 2px solid navy;. This is a popular way to underline headings.
⚠️ Warning: The style is required. A border with no style, such as border: 2px navy;, does not appear at all, because the default style is none.

Rounded Corners

border-radius rounds the corners of a box, even if it has no border. A radius of 50% on a square element makes it a circle, which is a common way to display profile photos.

.avatar {
    border-radius: 50%;
}

Try It

  1. Give each .card a border of 1px solid #ddd and a border-radius of 8px.
  2. Give the .card h3 headings a border-bottom of 2px solid teal.
  3. Make the .avatar images circular.

Margin

Margin uses the same shorthand pattern as padding. Most elements already have some margin from the browser's default stylesheet. For example, paragraphs and headings have margins above and below them, and the body has a margin of 8px all round, which is why your pages never quite touch the edge of the preview.

Centring With auto

Setting the left and right margins to auto tells the browser to share the leftover space equally between them, which centres a block element horizontally:

.container {
    max-width: 700px;
    margin: 0 auto;   /* 0 top and bottom, auto left and right */
}

This only works on a block element that is narrower than its parent. If it already fills the full width, there is no leftover space to share.

Collapsing Margins

When the bottom margin of one block element touches the top margin of the next, the two margins collapse into one. The gap between them is the larger of the two margins, not the total. For example, a paragraph with a 20px bottom margin followed by one with a 30px top margin are 30px apart, not 50px. This only happens with vertical margins, and it does not happen inside the flex and grid layouts in Lesson 9.

Try It

  1. Give each .card a margin of 0 auto 20px. The cards are now centred, with space between them.
  2. Give the body a margin of 0, and notice the page heading moves to the very edge of the preview. Then give the header a padding of 20px, and notice that its background colour fills the padding.

box-sizing

By default, width only sets the width of the content. Padding and border are then added on top. So your cards are not actually 300px wide:

  300px  content
+  40px  padding (20px on each side)
+   2px  border  (1px on each side)
= 342px  total width

This makes sizes hard to predict, especially when you change the padding later. Setting box-sizing: border-box changes how the width is measured, so that it includes the padding and border. A 300px card is then 300px wide, and the content shrinks to make room for the padding. The margin is never included.

Almost every modern website sets this for every element, using the universal selector, at the very top of the stylesheet:

* {
    box-sizing: border-box;
}

Try It

  1. Look at the Practice Area at the bottom of the page. The two boxes both have a width of 300px, but the second box has padding and a thick border, so it is much wider.
  2. Add the box-sizing rule from the example above to the very top of your CSS. Both practice boxes are now exactly the same width, and so are your cards.

The Box Model and Inline Elements

Inline elements follow the box model differently from blocks:

  • width and height have no effect. An inline element is always the size of its content.
  • Left and right padding and margins work as normal.
  • Top and bottom padding is drawn, but it does not push the lines above and below away, so it can overlap them. Top and bottom margins have no effect at all.

When you need an element to stay in the line of text, but be sized and spaced properly, use display: inline-block.

ℹ️ Info: Images are a special case. An <img> is inline by default, but because it is a "replaced" element, displaying an external file rather than text, its width and height do work.

Try It

  1. The navigation links in the header are inline <a> elements. Give the nav a links a padding of 10px 16px, a background-color of teal, a color of white and a width of 150px.
  2. Notice that the width has done nothing. The coloured padding is drawn, but the header has not grown to make room for it.
  3. Add display: inline-block; to the same rule. The links are now 150px wide, and the header grows taller to make room for their padding. Remove the width again, so each link fits its text.

Overflow

If a box has a fixed height and its content needs more room, the content overflows: it spills out of the box and over whatever comes next. The overflow property controls what happens:

  • visible: the content spills out. This is the default.
  • hidden: the extra content is cut off and cannot be seen.
  • scroll: the box always has scroll bars.
  • auto: the box gets scroll bars only when they are needed.
⚠️ Warning: Avoid overflow: hidden on boxes that contain text. If the user's text is larger than you expected, part of it is cut off and becomes impossible to read. Usually, the best fix for overflow is to remove the fixed height.

Try It

  1. Give the .bio paragraphs a height of 60px. The longer bio spills out of its box.
  2. Add overflow: auto;. The long bio now scrolls inside its box.
  3. Remove both declarations, so each bio is as tall as its text.

Check Your Page

Your card rules should be similar to these:

* {
    box-sizing: border-box;
}

.card {
    width: 300px;
    padding: 20px;
    margin: 0 auto 20px;
    background-color: white;
    border: 1px solid #ddd;
    border-radius: 8px;
}

.card h3 {
    padding: 0 0 10px;
    border-bottom: 2px solid teal;
}

.avatar {
    border-radius: 50%;
}

Also check that the cards are centred, the photos are circles, and the navigation links look like buttons that sit side by side.
