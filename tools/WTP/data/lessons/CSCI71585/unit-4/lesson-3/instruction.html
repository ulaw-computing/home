Comparison Operators

A comparison operator compares two values and gives a boolean result: true or false.

  • === equal to
  • !== not equal to
  • > greater than, and < less than
  • >= greater than or equal to, and <= less than or equal to
const age = 20;
console.log(age >= 18);         // true
console.log(age === 16);        // false
console.log("Leeds" === "leeds");   // false: strings are case-sensitive
⚠️ Warning: Do not confuse = and ===. A single = assigns a value, as you learned in the last lesson. Three equals signs, ===, compares two values. Writing = where you meant === is one of the most common mistakes in JavaScript.

Why Three Equals Signs?

JavaScript also has == and !=, with two equals signs. These convert the values to the same type before comparing them, using the type coercion you met in the last lesson. This leads to some confusing results:

console.log(5 == "5");    // true: "5" is converted to 5 first
console.log(5 === "5");   // false: a number is not a string
console.log(0 == "");     // true
console.log(0 === "");    // false

=== and !== are called strict equality: they only say two values are equal if they have the same type and the same value.

💡 Tip: Always use === and !==. If you need to compare values of different types, such as a number typed by the user, convert them yourself first with Number(), so that the comparison does exactly what you expect.

Logical Operators

Logical operators combine or reverse booleans:

  • && (and) is true only if both sides are true.
  • || (or) is true if at least one side is true.
  • ! (not) reverses a boolean: !true is false.
const age = 20;
const isStudent = true;

console.log(age >= 18 && isStudent);   // true: both are true
console.log(age < 16 || isStudent);     // true: one is true
console.log(!isStudent);                // false
ℹ️ Info: The | character is usually on the key to the left of Z on a UK keyboard, typed with Shift.

if Statements

An if statement runs a block of code only if a condition is true:

if (age >= 18) {
    console.log("You can watch this film.");
}
  • The condition goes in round brackets after if.
  • The code to run goes in curly braces { }. This is called a block.
  • The code in the block is indented, so it is easy to see that it belongs to the if.
  • There is no semicolon after the closing brace.

else

An else block runs when the condition is false. Exactly one of the two blocks always runs:

if (age >= 18) {
    console.log("You can watch this film.");
} else {
    console.log("Sorry, this film is for adults only.");
}

else if

To choose between more than two options, add else if blocks. JavaScript checks each condition in order, runs the block for the first one that is true, and skips the rest. If none are true, the final else runs:

let price;

if (age < 16) {
    price = 6;
} else if (age >= 65) {
    price = 7;
} else {
    price = 10;
}

Notice that price is declared before the if statement with let, and given a value inside it. If it were declared inside one of the blocks, it would only exist inside that block. You will learn more about this in the next lesson.

⚠️ Warning: The order of else if conditions matters. Once one condition is true, the rest are skipped completely, even if they would also be true. Put the most specific conditions first.

Combining Conditions

The cinema has a special offer: on Tuesdays, every ticket is half price. You can test this with a second, separate if statement after the first one:

if (day === "Tuesday") {
    price = price / 2;
}

The Ternary Operator

When an if and else only choose between two values, the ternary operator does the same job in one line:

// condition ? value if true : value if false
const message = age >= 18 ? "Adult ticket" : "Child ticket";

Read it as a question: "Is the age 18 or over? If so, use Adult ticket; otherwise, use Child ticket."

💡 Tip: The ternary operator is ideal for choosing between two short values. For anything longer, or with more than two options, a normal if statement is much easier to read.

Truthy and Falsy Values

A condition does not have to be a boolean. JavaScript can treat any value as true or false. Six values are falsy, meaning they count as false in a condition:

  • false
  • 0
  • "" (an empty string)
  • null
  • undefined
  • NaN

Every other value is truthy, including any non-empty string and any number other than zero. This gives a short way to check whether something has a value:

const nickname = "";

if (nickname) {
    console.log(`Welcome back, ${nickname}!`);
} else {
    console.log("Welcome back!");
}
⚠️ Warning: Be careful when 0 is a valid value. If a user's score is 0, then if (score) treats it as false, as if there were no score at all. In that case, compare it directly instead: if (score !== undefined).

Putting It Together: A Results Checker

On most MSc courses in the UK, a module mark is classified like this:

  • 70 or above: Distinction
  • 60 to 69: Merit
  • 50 to 59: Pass
  • Below 50: Fail

Try It

  1. The starter code declares a const called mark. Write an if and else if chain that sets a let variable called result to the correct classification.
  2. Display it in the #module-result element, as A mark of 65 is a Merit.
  3. Test your chain with the marks 70, 69, 50, 49 and 0. Testing the values on either side of each boundary, like this, is the best way to check conditions are correct.
  4. Using the ternary operator, create a const called passed that is "Yes" if the mark is 50 or over and "No" otherwise, and display it in #module-passed.

Check Your Page

Your results checker should be similar to this:

let result;

if (mark >= 70) {
    result = "Distinction";
} else if (mark >= 60) {
    result = "Merit";
} else if (mark >= 50) {
    result = "Pass";
} else {
    result = "Fail";
}

document.querySelector("#module-result").textContent = `A mark of ${mark} is a ${result}.`;

const passed = mark >= 50 ? "Yes" : "No";
document.querySelector("#module-passed").textContent = passed;

Also check that the ticket price is correct for children, older people, students and everyone else, and halves on Tuesdays.
