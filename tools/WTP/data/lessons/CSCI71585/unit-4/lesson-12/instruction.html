Tutorial

In this final lesson, you will bring together everything from this unit to build a complete interactive page: a session browser for the Beginners' Web Workshop, which displays every session from an array of data, and lets users filter and search them.

This is very close to what you will build in the next unit. There, the data will come from an API on the web rather than being written in your script, but the code that turns the data into a page, and makes it interactive, will be almost exactly the same.

The HTML and CSS are already written in the starter code, along with the data. Your job is the JavaScript. As in the consolidation lessons of the previous units, there are no step-by-step instructions: you have a brief, a plan and a checklist. If you are unsure how to do something, look back at the relevant lesson.


The Brief

The page must include the following features.

Rendering the Sessions (Lessons 8 and 9)

  • Every session in the sessions array is displayed as a card in the #session-list element.
  • Each card shows the session's title, time, speaker and description, and its level as a tag.
  • Cards are created with createElement and textContent, not innerHTML.
  • The level tag has the class level-tag, plus the session's level as a second class, so the starter CSS can colour it. For example, class="level-tag intermediate".

Filtering by Level (Lessons 3, 6 and 10)

  • Clicking a filter button shows only the sessions at that level. All shows every session.
  • Each button has a data-level attribute in the HTML, which your code should use to know which level was chosen.
  • The chosen button has aria-pressed="true", and every other filter button has aria-pressed="false". The starter CSS styles the chosen button from this attribute.

Searching (Lessons 2, 6 and 10)

  • Typing in the search box shows only the sessions whose title or speaker includes the search text, updating as the user types.
  • The search ignores capital letters, and any spaces at the start or end.
  • Search and level filter work together: searching for chen with Advanced chosen shows only Li Chen's advanced session.

Feedback (Lessons 9 and 10)

  • The #session-count element always shows how many sessions are displayed, such as Showing 3 of 8 sessions.
  • When no sessions match, the #empty-message is shown, and it is hidden otherwise.

Responsive Menu and Theme (Lesson 11)

  • On small screens, the Menu button opens and closes the navigation, with aria-expanded kept up to date.
  • The menu closes when a link is chosen, when Escape is pressed, and when the layout changes to desktop. The CSS breakpoint is 700px.
  • The theme button switches dark mode on and off, starting from the user's device setting, with aria-pressed kept up to date.

Plan Before You Build

The key to this page is the state pattern from Lessons 6 and 9. The page has two pieces of state: the chosen level, and the search text. Store them in two let variables at the top of your script:

let currentLevel = "all";
let searchText = "";

Then plan your code as a few small functions, each with one job:

  • createSessionCard(session) builds and returns one card from one session object.
  • getVisibleSessions() uses filter to return a new array of only the sessions that match both the current level and the current search text.
  • render() clears the list, creates a card for each visible session, and updates the count and the empty message.

Every event listener then follows the same two steps: update the state, then call render(). For example, the search box's listener updates searchText and calls render(), and a filter button's listener updates currentLevel and calls render().

💡 Tip: Inside getVisibleSessions, it is easier to work out the two conditions separately, as booleans, and then combine them with &&: 
const matchesLevel = currentLevel === "all" || session.level === currentLevel;
const matchesSearch = /* your search check here */;
return matchesLevel && matchesSearch;

Build in Stages

Build one feature at a time, and check that it works before starting the next. Use console.log to check your values at each step: for example, log getVisibleSessions() to check it returns the sessions you expect, before you try to display them.

  1. One card: write createSessionCard, and test it by appending one card for sessions[0].
  2. Every card: write render, displaying every session, with the count.
  3. Level filter: add currentLevel, getVisibleSessions with the level check only, and the filter button listeners.
  4. Search: add searchText, the search check and the search box listener.
  5. Empty state: show and hide the empty message.
  6. Menu and theme: add the code from Lesson 11, adapted for this page.
💡 Tip: If a feature stops working after a change, undo your last change and check that it works again, then make the change again in smaller steps. Small, tested steps are much faster in the end than writing everything at once.

Debugging Challenge

Each of the snippets below is from a session browser that does not work properly. The problem is described, but not the cause. For each one, find the bug by reading the code carefully. You can check your answer by revealing it.

1. The Beginner filter shows nothing

Clicking All shows every session, but clicking Beginner shows none at all, even though there are three beginner sessions.

const matchesLevel = currentLevel === "all" || session.level === "Beginner";
Reveal the answer

The code compares the session's level with the string "Beginner", with a capital B, but the levels in the data are all lowercase, such as "beginner". Strings are case-sensitive, so no session ever matches. It also checks for beginner sessions whichever button was clicked. It should compare with the current state instead: session.level === currentLevel.

2. The count never changes

The filters and search work, but the count always says Showing 8 of 8 sessions.

const visibleSessions = getVisibleSessions();
// ...
countElement.textContent = `Showing ${sessions.length} of ${sessions.length} sessions`;
Reveal the answer

The first number uses sessions.length, the length of the full array, which is always 8. It should use visibleSessions.length, the length of the filtered array.

3. Cards multiply as you type

Every time a letter is typed in the search box, another full set of matching cards appears below the last one.

function render() {
    getVisibleSessions().forEach((session) => {
        sessionList.append(createSessionCard(session));
    });
}
Reveal the answer

render adds new cards without removing the old ones first. It needs sessionList.replaceChildren(); as its first line.

4. Every title is blank

The cards appear, with the right speakers and times, but there is no title on any card.

const title = document.createElement("h3");
title.textContent = session.tittle;
Reveal the answer

The property name is misspelt: tittle instead of title. Reading a property that does not exist gives undefined, and setting textContent to undefined leaves the heading empty.

5. The search only works for exact capitals

Searching for grid finds the flexbox and grid session, but searching for Grid, with a capital G, finds nothing.

const matchesSearch = session.title.toLowerCase().includes(searchText);
// ...
searchInput.addEventListener("input", () => {
    searchText = searchInput.value.trim();
    render();
});
Reveal the answer

The session's title is converted to lowercase, but the search text is not, so a search containing any capital letter can never match. The search text needs .toLowerCase() too: searchText = searchInput.value.trim().toLowerCase();.


Extension Challenges

If you finish early, try one or more of these:

  • Saved sessions: add a Save button to each card. Using event delegation, store the IDs of saved sessions in an array, show a count of saved sessions, and change the button's text to Saved for sessions already saved.
  • Search descriptions: make the search also look in each session's description.
  • Sorting: add buttons to sort the sessions by time or by title. Look up the array sort method on MDN.

Check Your Page

Your page is complete when:

  • All eight sessions are shown when the page loads, with the count Showing 8 of 8 sessions.
  • Each filter button shows only its level, and only the chosen button is highlighted.
  • Searching for chen, CHEN or chen (with spaces) finds Li Chen's sessions.
  • The filter and search work together, and the empty message appears when nothing matches.
  • Every button works with the keyboard, using Tab and Enter.
  • In a narrow pop-out preview, the menu opens and closes, including with Escape, and closes when the window is widened to the desktop layout.
  • The theme button switches between light and dark mode.
  • No card is built with innerHTML.

Make sure you download your work using the Download button. You will use the same patterns in the next unit, with real data from the web.


Unit Summary

In this unit, you have learned to:

  • Add JavaScript to a page, and use the console to check what your code is doing.
  • Store values in variables, and work with strings, numbers and booleans.
  • Make decisions with comparison operators and conditionals.
  • Write reusable functions that take parameters and return values.
  • Find and change elements on the page through the DOM.
  • Respond to clicks, typing and key presses with events.
  • Work with lists of data using arrays, loops and array methods.
  • Group related data into objects, and work with arrays of objects.
  • Build page content from data, safely, and update it when the data changes.
  • Build accessible accordions, tabs and live filters.
  • Make JavaScript work with responsive design and the user's own preferences.
