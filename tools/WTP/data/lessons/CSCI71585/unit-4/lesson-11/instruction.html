Tutorial

In the CSS unit, you built pages that adapt to any screen size, using fluid layouts and media queries. Some responsive patterns, though, need JavaScript as well. The most common is the mobile navigation menu: on a small screen there is no room for every link, so the links are hidden behind a button that opens and closes them. In this lesson you will build one, learn how JavaScript can respond to media queries, and use the user's own device settings, such as dark mode, to decide how the page behaves.

The starter code contains a page for a coding club, with its CSS already written mobile-first. As in the CSS unit, you will test it in the pop-out preview, so open it now and keep it beside the editor. As before, complete each Try It section in the editor before moving on.


CSS for Layout, JavaScript for State

The most important principle in this lesson is a division of labour:

  • CSS decides the layout at each screen size, using media queries, exactly as in the CSS unit. It decides whether the menu button is visible, and what an open or closed menu looks like.
  • JavaScript only changes the state, usually by adding or removing a class, and updating the ARIA attributes to match.

JavaScript should never be setting widths, positions or display values that a media query could handle. CSS is faster, works before any JavaScript has loaded, and keeps all of the layout in one place.

Look at the starter CSS to see how this works for the menu:

/* Small screens: the menu button shows, and the menu is closed */
.site-nav {
    display: none;
}

/* When JavaScript adds the open class, the menu shows */
.site-nav.open {
    display: block;
}

/* Large screens: no button, and the menu always shows */
@media (min-width: 700px) {
    .menu-button {
        display: none;
    }

    .site-nav {
        display: block;
    }
}

The JavaScript does not need to know about screen sizes at all. It only adds or removes the open class, and the CSS decides what that means at each size.

  1. In the pop-out preview, make the window narrow until the layout status reads mobile. The navigation links have disappeared, and a Menu button has appeared, which does nothing yet.
  2. Make the window wide. The button disappears, and the links appear in a row.

The Mobile Menu

The menu button in the starter HTML already has the attributes it needs:

<button type="button" class="menu-button" aria-expanded="false" aria-controls="site-nav">Menu</button>
<nav class="site-nav" id="site-nav">...</nav>

This is the same pattern as the accordion in the last lesson: aria-controls connects the button to the menu, and aria-expanded tells screen reader users whether it is open.

The classList.toggle() method has a useful feature: it returns true if it has just added the class, and false if it has just removed it. That is exactly the value aria-expanded needs:

const menuButton = document.querySelector(".menu-button");
const siteNav = document.querySelector("#site-nav");

menuButton.addEventListener("click", () => {
    const isOpen = siteNav.classList.toggle("open");
    menuButton.setAttribute("aria-expanded", String(isOpen));
});

Try It

  1. In the JS tab, add the menu code from the example above.
  2. In a narrow pop-out preview, click the Menu button to open and close the menu.
  3. Press Tab to reach the button, and press Enter to open the menu. Keep pressing Tab, and check that you can reach every link in the menu.

Closing the Menu

Users expect a menu to close in a few situations, as well as when they click the button again:

  • When they choose a link. On this page, the links jump to sections of the same page, so the menu would otherwise stay open on top of the content they wanted to see.
  • When they press Escape. This is the standard way to close anything that has opened, and it is essential for keyboard users. Focus should then return to the menu button, so the user is not left somewhere unexpected on the page.

Since the menu now needs to close from several places, it makes sense to write a closeMenu function:

function closeMenu() {
    siteNav.classList.remove("open");
    menuButton.setAttribute("aria-expanded", "false");
}

Try It

  1. Add the closeMenu function.
  2. Add a click listener to siteNav, using event delegation from Lesson 9: if event.target.closest("a") finds a link, call closeMenu(). Open the menu and choose a link, and check that the menu closes.
  3. Add a keydown listener to the document. If the key is "Escape" and the menu is open (siteNav.classList.contains("open")), call closeMenu(), then move focus back to the button with menuButton.focus().

Media Queries in JavaScript

Occasionally, JavaScript does need to know which layout is being used. window.matchMedia() takes a media query, written exactly as in CSS, and returns an object describing it. Its matches property is true if the query currently applies:

const desktopQuery = window.matchMedia("(min-width: 700px)");

console.log(desktopQuery.matches);   // true on a wide screen, false on a narrow one

The object also fires a change event whenever the query starts or stops applying, such as when the user resizes the window across the breakpoint:

desktopQuery.addEventListener("change", () => {
    console.log(`Desktop layout: ${desktopQuery.matches}`);
});

A real use for this is the menu. If a user opens the mobile menu, then widens their window to the desktop layout, the menu's open class and aria-expanded="true" are left behind. If they later narrow the window again, the menu would appear already open. Closing the menu whenever the layout changes to desktop avoids this.

⚠️ Warning: Use the same breakpoint in JavaScript as in your CSS. If the CSS switches layout at 700px but the JavaScript checks for 600px, the two disagree for every width in between.

Try It

  1. Create the desktopQuery from the example above.
  2. Write a function called updateLayoutStatus that displays Layout: desktop or Layout: mobile in the #layout-status element, using desktopQuery.matches and the ternary operator. Call it once when the page loads.
  3. Add a change listener to desktopQuery that calls updateLayoutStatus, and also calls closeMenu if the layout is now desktop.
  4. In a narrow pop-out preview, open the menu, then widen the window to the desktop layout, then narrow it again. The menu is closed, and the status updates each time the layout changes.

Why Not Use the resize Event?

The window also has a resize event, which fires every time the window's size changes. You will see it in older code, but it is rarely the right choice:

  • It fires many times a second while the window is being resized, so code in it runs far more often than needed, which can make the page slow.
  • Most things people use it for, such as changing a layout at a certain width, are better done with a CSS media query.
  • When JavaScript does need to know about a breakpoint, matchMedia only fires its change event at the moment the breakpoint is crossed.

Respecting User Preferences

Media queries can also test the settings the user has chosen on their own device. In CSS, these are written in a media query, and in JavaScript, they can be checked with matchMedia in exactly the same way.

Dark Mode

Many people set their device to a dark theme, which some find easier on the eyes, especially at night, and which can save battery on some screens. The prefers-color-scheme media feature tells you which they have chosen:

const prefersDark = window.matchMedia("(prefers-color-scheme: dark)").matches;

A good theme toggle starts from the user's device setting, and then lets them change it for this page with a button. The starter CSS has a dark class for the <body>, which changes the page's colours.

The theme button uses aria-pressed, which describes a toggle button: a button that stays on or off, like a light switch. Screen readers announce it as, for example, "Dark mode, toggle button, pressed".

const themeButton = document.querySelector("#theme-button");

function setDarkMode(isDark) {
    document.body.classList.toggle("dark", isDark);
    themeButton.setAttribute("aria-pressed", String(isDark));
}

setDarkMode(prefersDark);   // start from the device setting

Here, toggle is given a second argument. Instead of flipping the class, toggle("dark", isDark) adds it if isDark is true, and removes it if it is false.

Try It

  1. Add the prefersDark check, the setDarkMode function and the call to it.
  2. Add a click listener to themeButton that calls setDarkMode with the opposite of the current state: !document.body.classList.contains("dark").
  3. Click the button to switch between light and dark.
ℹ️ Info: If your device is set to a dark theme, the page starts in dark mode. You can usually change this in your operating system's display or appearance settings, to test both. The user's choice on this page is forgotten when the page reloads. Remembering it needs browser storage, which you will meet in a later unit.

Reduced Motion

Animation and movement on a page, such as smooth scrolling or sliding panels, can make some people feel dizzy or unwell, particularly people with vestibular (inner ear) disorders. Most devices have a setting to reduce motion, and the prefers-reduced-motion media feature tells you whether the user has turned it on.

The Back to top button at the bottom of the page scrolls back to the top. Smooth scrolling looks good, but it should only be used if the user has not asked for reduced motion:

const reduceMotion = window.matchMedia("(prefers-reduced-motion: reduce)").matches;

document.querySelector("#back-to-top").addEventListener("click", () => {
    window.scrollTo({
        top: 0,
        behavior: reduceMotion ? "auto" : "smooth"
    });
});

window.scrollTo() scrolls the page to a position. Its behavior option is "smooth" for an animated scroll, or "auto" to jump straight there.

Try It

  1. Add the reduced motion check and the Back to top listener. Scroll down the page and click the button.
💡 Tip: Whenever you add movement to a page, in CSS or JavaScript, check prefers-reduced-motion first. You will use it again with CSS animations in the next unit.

Check Your Page

Your menu and layout code should be similar to this:

const menuButton = document.querySelector(".menu-button");
const siteNav = document.querySelector("#site-nav");
const desktopQuery = window.matchMedia("(min-width: 700px)");

function closeMenu() {
    siteNav.classList.remove("open");
    menuButton.setAttribute("aria-expanded", "false");
}

function updateLayoutStatus() {
    document.querySelector("#layout-status").textContent =
        desktopQuery.matches ? "Layout: desktop" : "Layout: mobile";
}

menuButton.addEventListener("click", () => {
    const isOpen = siteNav.classList.toggle("open");
    menuButton.setAttribute("aria-expanded", String(isOpen));
});

siteNav.addEventListener("click", (event) => {
    if (event.target.closest("a")) {
        closeMenu();
    }
});

document.addEventListener("keydown", (event) => {
    if (event.key === "Escape" && siteNav.classList.contains("open")) {
        closeMenu();
        menuButton.focus();
    }
});

desktopQuery.addEventListener("change", () => {
    updateLayoutStatus();
    if (desktopQuery.matches) {
        closeMenu();
    }
});

updateLayoutStatus();

Also check, in both a narrow and a wide pop-out preview, that the theme button switches between light and dark, and the Back to top button works.
