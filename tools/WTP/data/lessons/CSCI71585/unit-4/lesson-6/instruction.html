In the last lesson, your JavaScript changed the page as soon as it loaded. That is useful, but the real power of JavaScript is making the page respond to the user: something happens when they click a button, type in a box or press a key. These moments are called events, and in this lesson you will learn how to listen for them and respond.

The starter code contains an ordering page for a coffee shop. By the end of the lesson, it will build an order as the user clicks and types. As before, keep the console open, and complete each Try It section in the editor before moving on.


What Is an Event?

An event is something that happens on the page, which the browser announces so that your code can respond. Some of the most common are:

  • click: the user clicks an element, or presses Enter or Space on a focused button.
  • input: the value of a text box, or other form field, changes.
  • change: the user finishes changing a field, such as choosing an option from a dropdown.
  • keydown: the user presses a key.

Code that waits for events and responds to them is called event-driven. Instead of running once from top to bottom and finishing, the page sits waiting, and runs your functions whenever the user does something.


Listening for Events

To respond to an event, you add an event listener to an element, with the addEventListener method. It takes two arguments: the type of event, as a string, and the function to call when it happens, called the event handler:

const welcomeButton = document.querySelector("#welcome-button");

function showWelcome() {
    document.querySelector("#welcome-message").textContent = "Welcome to Kirkgate Coffee!";
}

welcomeButton.addEventListener("click", showWelcome);

This says: "when welcomeButton is clicked, call showWelcome". The handler is a callback, just like the function you passed to setTimeout in Lesson 4.

⚠️ Warning: Pass the function without brackets: addEventListener("click", showWelcome). With brackets, showWelcome() runs immediately, when the page loads, and the listener is given its result instead of the function, so nothing happens on click.
ℹ️ Info: Event types are always lowercase, with no "on" at the start: "click", not "onClick". In older code, you may see handlers written as HTML attributes, such as <button onclick="showWelcome()">. This mixes JavaScript into the HTML, in the same way that inline styles mix CSS into it, so always use addEventListener instead.

  1. In the JS tab, add the code from the example above. Click the Say hello button in the preview, and check that the welcome message appears.
  2. Add brackets after showWelcome in the addEventListener call. Notice the message now appears straight away, without a click. Remove the brackets again.

Arrow Functions as Handlers

When a handler is short and only used in one place, it is common to write it as an arrow function, directly inside addEventListener:

welcomeButton.addEventListener("click", () => {
    document.querySelector("#welcome-message").textContent = "Welcome to Kirkgate Coffee!";
});

Both styles work in exactly the same way. A named function is better when the same handler is used by several elements, or when it is long enough to deserve its own name.


Keeping Track of State

Most interactive pages need to remember things between events: how many items are in the basket, which tab is open, what the user has chosen. This information is called the page's state, and it is usually stored in let variables declared at the top of the script, outside any function, so that every handler can use and update them.

A good pattern is to keep the state in variables, and write one function that updates the page to match the current state. Every handler then changes the state and calls that function:

let itemCount = 0;

function updateOrder() {
    document.querySelector("#item-count").textContent = itemCount;
}

document.querySelector("#add-button").addEventListener("click", () => {
    itemCount++;
    updateOrder();
});

This means the code that changes the page is written once, in one place, however many different buttons can change the order. You will use this pattern for the rest of the unit.

The Event Object

When the browser calls an event handler, it passes in an event object as the first argument, containing information about what happened. You can receive it by giving the handler a parameter, usually called event:

button.addEventListener("click", (event) => {
    console.log(event.target);   // the element that was clicked
});

The most useful property is event.target: the element the event happened on. This lets one handler work for several elements, and find out which one was used.

Data Attributes

To store extra information on an element for JavaScript to use, HTML has data attributes: any attribute whose name starts with data-. JavaScript reads them through the element's dataset property, without the data- part:

<button type="button" class="drink-button" data-drink="Latte" data-price="3.20">Latte</button>
console.log(button.dataset.drink);   // "Latte"
console.log(button.dataset.price);   // "3.20", a string

Data attribute values are always strings, so remember to convert them with Number() before doing any maths with them.

Responding to Typing

Form fields have a value property, which is whatever is currently in the field. The input event fires every time the value changes, so it is ideal for updating the page live, as the user types:

const nameInput = document.querySelector("#customer-name");

nameInput.addEventListener("input", () => {
    console.log(nameInput.value);
});
💡 Tip: Use .trim() from Lesson 2 on values the user has typed, to remove any accidental spaces at the start and end. Remember that value is always a string, even in a number field.

Keyboard Events

The keydown event fires when a key is pressed. Its event object has a key property, containing the name of the key, such as "a", "Enter", "Escape" or "ArrowUp":

document.addEventListener("keydown", (event) => {
    console.log(event.key);
});

Adding the listener to document means it responds to key presses anywhere on the page.

⚠️ Warning: Be careful with keyboard shortcuts that use single letters. A user typing their name in a text box presses letter keys too, and screen reader users rely on many single keys to navigate. Keys such as Escape are much safer choices.

Accessible Interactive Elements

Anything the user can click to make something happen should be a real <button> element, not a <div> or <span> with a click listener. Buttons come with essential behaviour built in:

  • They can be reached with the Tab key, and show a focus outline.
  • They respond to Enter and Space, which fire the click event, so your click handler works for keyboard users too.
  • Screen readers announce them as buttons, so users know they can press them.

A <div> has none of this. To make it work for everyone, you would have to add all of it yourself.

💡 Tip: Remember from the HTML unit that a button inside a form submits the form by default. Give buttons that only run JavaScript type="button", as every button on the starter page does.
ℹ️ Info: Some elements have their own default behaviour when an event happens: a link goes to its address when clicked, and a form is submitted. The event object's event.preventDefault() method stops this default behaviour, so that your JavaScript can handle the event instead. You will use this with forms in the next unit.

Check Your Page

Your order code should be similar to this:

let itemCount = 0;
let total = 0;

function updateOrder() {
    document.querySelector("#item-count").textContent = itemCount;
    document.querySelector("#order-total").textContent = `£${total.toFixed(2)}`;
}

function addDrink(event) {
    total += Number(event.target.dataset.price);
    itemCount++;
    console.log(`Added: ${event.target.dataset.drink}`);
    updateOrder();
}

function clearOrder() {
    itemCount = 0;
    total = 0;
    updateOrder();
}

document.querySelectorAll(".drink-button").forEach((button) => {
    button.addEventListener("click", addDrink);
});

document.querySelector("#clear-button").addEventListener("click", clearOrder);

document.addEventListener("keydown", (event) => {
    if (event.key === "Escape") {
        clearOrder();
    }
});

Also check that the order name updates as you type, the milk choice appears when you choose one, and every button works using the keyboard: press Tab to reach it and Enter to press it.
