Tutorial

In the last two units, you used HTML to describe the content of a page and CSS to control how it looks. Both are static: once the page has loaded, it stays the same until the user goes somewhere else. In this unit, you will learn JavaScript, the programming language that makes pages respond to the people using them: menus that open, forms that check what you type, content that updates without reloading the page.

This first lesson covers the foundations: what JavaScript is, how to add it to a page, and how to see what your code is doing. Whenever you see a Try It section, make that change in the editor before moving on.


What Is JavaScript?

JavaScript is a programming language. Unlike HTML and CSS, which describe a page, JavaScript gives the browser instructions to follow: do this, then this, and if this happens, do that instead.

The three languages of the web each have their own job:

  • HTML is the content and structure: what is on the page.
  • CSS is the presentation: how it looks.
  • JavaScript is the behaviour: what it does.

Some of the things JavaScript does on almost every website are:

  • Responding to the user, such as opening a menu when a button is clicked.
  • Changing the page after it has loaded, such as adding an item to a basket.
  • Checking information before it is sent, such as an email address in a form.
  • Fetching new data from a server without reloading the page, such as new messages in a chat. You will learn how to do this in the next unit.

The JavaScript in this unit runs inside the user's browser, on their own device. This is called client-side code, because it runs on the client (the browser) rather than on the web server.

ℹ️ Info: Despite the name, JavaScript has nothing to do with the Java programming language. The name was chosen for marketing reasons when it was created in 1995, because Java was popular at the time. The official standard for the language is called ECMAScript, and JavaScript can also run outside the browser, for example on servers, using a tool called Node.js.

Adding JavaScript to a Page

JavaScript is added to a page with the <script> element. Just as with CSS, the code can be written inside the element, or kept in a separate file:

<!-- Internal: the code is inside the element -->
<script>
    console.log("Hello from the page!");
</script>

<!-- External: the code is in a separate file -->
<script src="script.js"></script>

For the same reasons as external stylesheets, external scripts are usually best: one file can be shared by every page of a site, and the HTML and the JavaScript stay separate. Notice that an external <script> still needs its closing tag, even though it is empty.

ℹ️ Info: In this platform, the JS tab is your external script, and the starter HTML already contains a <script src="script.js"> element that links to it. When you click Download, your JavaScript is saved as script.js, so the link still works on your own computer.

Where to Put the Script

The browser reads an HTML page from top to bottom, building the page as it goes. When it reaches a <script> element, it stops and runs the script straight away, before reading the rest of the page.

This matters, because most JavaScript works with elements on the page. If the script runs before the browser has reached those elements, they do not exist yet, and the code fails. For this reason, the usual place for a script is at the end of the body, just before </body>, so that the whole page has been built before the script runs:

<body>
    <h1>My Page</h1>
    <p id="output"></p>

    <script src="script.js"></script>
</body>
ℹ️ Info: You will also see scripts placed in the <head> with a defer attribute: <script src="script.js" defer></script>. defer tells the browser to download the script straight away, but wait to run it until the page has been built. This works well on real websites, but this platform's preview does not support it, so in these lessons, always place your script just before </body>.

The Console

When you write JavaScript, you need a way to see what your code is doing. Every browser has built-in developer tools, and one of them is the console: a panel that shows messages from your code.

To open the console:

  • Chrome or Edge on Windows: press Ctrl + Shift + J, or press F12 and click the Console tab.
  • Chrome on a Mac: press Cmd + Option + J.
  • Firefox: press Ctrl + Shift + K (or Cmd + Option + K on a Mac).

The console opens as a panel at the side or bottom of the browser window. You can keep it open while you work.

Writing to the Console

console.log() writes a message to the console. Whatever you put between the brackets is displayed:

console.log("Hello, world!");
console.log(42);
console.log(2 + 3);

Text must be written in quotes, so that JavaScript knows it is text and not code. Numbers and calculations do not need quotes: console.log(2 + 3) displays 5, because JavaScript works out the answer first. console.log("2 + 3"), with quotes, displays the text 2 + 3 exactly as written.

The console is a tool for you, the developer. Users never see it, so it is not a way to show information to the people using your page. You will learn how to do that later in this lesson.

Try It

  1. Open the console in your browser. The starter JavaScript contains one line, which writes The script is connected! to the console. Check that you can see the message.
  2. Below that line in the JS tab, add console.log("Hello, world!"); and check that it appears in the console.
  3. Add console.log(2 + 3); and console.log("2 + 3"); and compare the two results.

The Console in This Platform

The preview runs your JavaScript again every time you change your code, so the console fills up with repeated messages as you type. Before checking your output, clear the console: click the 🚫 button at the top of the console, or press Ctrl + L (Cmd + K on a Mac) while the console is selected.

ℹ️ Info: Repeated messages do not mean your code is running twice by mistake, or that something is wrong. They are simply left over from earlier runs of the preview. The console is there so you can see the output of your code; clear it and check again whenever you are unsure which messages are new.

The fullscreen preview runs your code too, so its messages appear in the same console. The pop-out preview is a separate window, so its messages only appear if you open the console in that window.

💡 Tip: Get into the habit of clearing the console, making a change, then checking the new output. If you are ever unsure which messages are new, clear the console and make any small change in the editor to run your code again.

Try It

  1. Change the text of your Hello, world! message, one letter at a time. Notice that the console fills up with repeated messages.
  2. Clear the console, then make one more small change. Now only the latest output is shown.

Statements and Syntax

A JavaScript program is made up of statements: individual instructions, such as console.log("Hello");. The browser runs them one at a time, from top to bottom.

  • Each statement ends with a semicolon. JavaScript can often work out where a statement ends without one, but leaving them out occasionally causes confusing bugs, so always include them.
  • JavaScript is case-sensitive. console.log works, but Console.log and console.Log do not. This is different from HTML, where <P> and <p> are the same.
  • Whitespace is ignored, as in HTML and CSS, so you can use blank lines and indentation to make your code readable.
  • Brackets and quotes come in pairs. Every opening ( needs a closing ), and every opening quote needs a closing quote of the same kind.

Comments

JavaScript has two kinds of comment, and the browser ignores both:

// A single-line comment: everything after the two slashes is ignored

/*
   A multi-line comment,
   just like in CSS
*/

console.log("Hello"); // A comment at the end of a line
⚠️ Warning: Remember the CSS unit: // is not a comment in CSS, and silently breaks the next rule. It only works in JavaScript. /* */ works in both, so if you are ever unsure, use that.

Try It

  1. Add a single-line comment at the top of your JavaScript, describing what the file is for.
  2. Put // at the start of your console.log("2 + 3"); line. Clear the console and check that the message no longer appears. This is called commenting out a line, and it is a quick way to switch code off while you test something.

Showing Output on the Page

The console is for developers, but most of the time, you want your JavaScript to change what the user sees. You will learn exactly how this works in Lesson 5. Until then, you can use this pattern to put text into an element on the page:

document.querySelector("#output").textContent = "Hello from JavaScript!";

Read it from left to right: in the page (document), find the element with the ID output (querySelector("#output")), and set its text (textContent) to the message. The selector inside the brackets is written exactly like a CSS selector.

Try It

  1. The starter HTML contains an empty paragraph with the ID output. Add the line from the example above to the end of your JavaScript, and check that the message appears on the page in the preview.
  2. Change the message to your own name, and check that the page updates.

Why the Script Goes at the End

You can now see for yourself why the position of the <script> element matters.

Try It

  1. In the HTML tab, move the <script src="script.js"></script> line from the end of the body into the <head>, just below the <link>.
  2. Look at the preview. Your message has gone from the page. The script ran before the browser had built the paragraph, so querySelector could not find it, and the text had nowhere to go.
  3. Move the script back to just before </body>, and check that the message returns.
💡 Tip: Remember this. If your code is meant to change the page but nothing happens, check two things first: that the selector matches the element exactly, and that the script is just before </body>.

Check Your Page

Your JavaScript should look similar to this, with your own comment and name:

// Practising the basics of JavaScript
console.log("The script is connected!");
console.log("Hello, world!");
console.log(2 + 3);
// console.log("2 + 3");

document.querySelector("#output").textContent = "Hello from Sam!";

Also check that the <script> element is just before </body>, and your message appears on the page.
