Tutorial

So far, your JavaScript has changed elements that were already written in the HTML. But on most modern websites, much of the content is built by JavaScript, from data: a list of search results, the products in a shop, the messages in a chat. The data might be written in the script, or, as you will see in the next unit, fetched from a server. In this lesson you will learn how to create elements from an array of objects, add them to the page, and update the page whenever the data changes.

This is the most important skill in the unit, and everything in it will be used again when you work with real data from the web. The starter code contains a reading list for a book club, with the data already written in the script. As before, keep the console open, and complete each Try It section in the editor before moving on.


Data First

When content is built from data, the data becomes the single source of truth. The page is just a picture of the data at one moment. To change what the page shows, you never edit the page directly: you change the data, and then rebuild the page from it. This is the same state pattern you used in Lesson 6, applied to whole lists.

change the data  →  rebuild the page from the data

This approach has a big advantage: the data and the page can never get out of step, because the page is always built from the data.


Creating Elements

document.createElement() creates a new element. It takes the tag name, as a string, without angle brackets:

const heading = document.createElement("h3");
heading.textContent = "The Secret Garden";
heading.classList.add("book-title");

The new element exists, and you can set its text, classes and attributes exactly as you did in Lesson 5. But it is not on the page yet. It only exists in JavaScript until you add it to an element that is already on the page.

Adding Elements to the Page

  • parent.append(child) adds the child as the last thing inside the parent. It can add several elements at once: parent.append(first, second).
  • parent.prepend(child) adds it as the first thing inside the parent.
const bookList = document.querySelector("#book-list");
bookList.append(heading);
ℹ️ Info: You will also see appendChild() in older code. It works in a similar way to append(), but can only add one element at a time.

Building a Card From an Object

Each book should appear as a card, containing several elements. The best way to do this is to write a function that takes one object, builds the elements for it, and returns the finished card:

function createBookCard(book) {
    const card = document.createElement("article");
    card.classList.add("book-card");

    const title = document.createElement("h3");
    title.textContent = book.title;

    const author = document.createElement("p");
    author.textContent = `by ${book.author}`;

    const details = document.createElement("p");
    details.classList.add("book-details");
    details.textContent = `${book.genre} · ${book.pages} pages`;

    card.append(title, author, details);
    return card;
}

Like convertToMiles in Lesson 4, this function does not change the page itself: it returns a value, here an element, which the code that calls it can add to the page wherever it is needed.

⚠️ Warning: You will often see cards built by writing a template literal of HTML and setting it with innerHTML, such as card.innerHTML = `<h3>${book.title}</h3>`. This is shorter, but as you learned in Lesson 5, it is dangerous with any data you did not write yourself. When the data comes from users or from another website, a title containing HTML could run harmful code on your page. Creating elements and setting textContent is always safe, so use it for anything built from data.

Rendering the Whole List

To display every book, loop through the array, create a card for each object, and append it. Putting this in a function, usually called render, means you can rebuild the list whenever the data changes:

function render() {
    bookList.replaceChildren();   // remove the old cards first

    books.forEach((book) => {
        bookList.append(createBookCard(book));
    });
}

render();

replaceChildren(), called with nothing in its brackets, removes everything inside the element. This matters: without it, every call to render would add a second copy of every card below the first.

Adding Items

Because the page is built from the data, adding a new item takes two steps: add it to the array, and call render again.

function addBook(title, author) {
    books.push({
        id: Date.now(),
        title: title,
        author: author,
        genre: "Unknown",
        pages: 0
    });
    render();
}

Each book needs a unique id. Date.now() returns the number of milliseconds since 1 January 1970, which is different every time it is called, so it makes a quick and simple unique ID.

Removing Items

Each card should have a Remove button. To know which book to remove, the button needs to carry the book's ID, using a data attribute:

const removeButton = document.createElement("button");
removeButton.type = "button";
removeButton.classList.add("remove-button");
removeButton.textContent = "Remove";
removeButton.dataset.id = book.id;

Setting dataset.id creates a data-id attribute on the button. To remove the book, you change the data, then render again. filter is ideal for this, since it creates a new array without the item you want to remove:

function removeBook(id) {
    books = books.filter((book) => book.id !== id);
    render();
}

Because this replaces the whole array with a new one, books must be declared with let, not const. The starter code already does this.

ℹ️ Info: Elements also have a remove() method, which deletes the element itself from the page: card.remove(). That changes the page but not the data, so the book would come back the next time the list is rendered. Changing the data and rendering again keeps them in step.

Listening for Clicks: Event Delegation

There is a problem with adding a click listener to each Remove button. Every time the list is rendered, the old buttons are thrown away and brand new ones are created, which do not have listeners. You could add a listener to each new button inside createBookCard, but there is a better way.

When you click an element, the click event also travels up through all of its ancestors, an effect called bubbling. So a click on a Remove button is also a click on the card, and on the #book-list element that contains every card. This means you can add one listener to the list itself, which never changes, and work out which button was clicked from event.target:

bookList.addEventListener("click", (event) => {
    const button = event.target.closest(".remove-button");

    if (button) {
        removeBook(Number(button.dataset.id));
    }
});
  • closest(".remove-button") looks at the clicked element, then its parent, then its parent's parent, and so on, and returns the first one that matches the selector, or null if none do.
  • If the click was not on a Remove button, such as on a book's title, button is null, so nothing happens.
  • Data attributes are strings, so the ID is converted back to a number before comparing, since "5" !== 5.

This technique is called event delegation: one listener on a parent handles events for all of its children, including children that are created later.

Empty States

When a list is empty, a blank space is confusing: the user cannot tell whether the list is empty, still loading or broken. A short message explaining that there is nothing to show is called an empty state.

Check Your Page

Your render function and listener should be similar to these:

function render() {
    bookList.replaceChildren();

    books.forEach((book) => {
        bookList.append(createBookCard(book));
    });

    document.querySelector("#book-count").textContent = `${books.length} books on the list`;

    const emptyMessage = document.querySelector("#empty-message");
    if (books.length === 0) {
        emptyMessage.classList.remove("hidden");
    } else {
        emptyMessage.classList.add("hidden");
    }
}

bookList.addEventListener("click", (event) => {
    const button = event.target.closest(".remove-button");

    if (button) {
        removeBook(Number(button.dataset.id));
    }
});

render();

Also check that new books can be added, and only when a title has been typed.
